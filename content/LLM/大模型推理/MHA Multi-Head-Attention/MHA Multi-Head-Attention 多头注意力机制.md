# 1. 什么是多头 Multi-Head？

大语言模型 Transformer 架构中, token 的 embedding 向量在进入第一层神经网络的 self-attention 之前，要首先经过三个矩阵$W_Q、W_K、W_V$(分别与这三个矩阵做乘法), 得到向量 Q，K，V。然后将 Q，K，V 这三个向量按照一个固定的维数切割开，切割后的每个部分，叫做一个head。因此，每个 head 是划分为固定维度的向量。

例如，输入 token 的 embedding 是 4096 维。它先分别乘以 $W_Q、W_K、W_V$ 三个权重矩阵，得到 Q、K、V 向量(每个仍是 4096 维)。Q, K, V 向量，叫做一个 token embedding 的投影向量。
然后把这 3 个 4096 维的投影向量切成 64 段, 每段 64 维。这 64 个 head 做注意力计算的时候，是独立计算的，互不影响，可以并行计算。

这就是 <font color="#45ce6e">「Multi-head attention, 多头注意力机制」</font>。有几点需要特别注意

> [!NOTE] 特别注意
> - 按 head 切分的时候，切分的是投影后 Q / K / V 向量，而不是原始 embedding 向量本身。虽然在标准实现里 $W_Q$ 是一个 4096×4096 的大矩阵,数学上等价于"每个 head 有自己独立的 128 维投影矩阵 $W_Q^i$ (4096×128)"。工程上合并成一个大矩阵是为了一次 GEMM 算完, 效率更高.
> - **每个 head 在自己的 128 维子空间里独立算 attention**：$QK^T$ → scale → softmax → 乘 V，得到 128 维输出。
> - **最后拼接 + 输出投影**：64 个 head 各输出 64 维，concat 回 4096 维，再过一个 W_O (4096×4096) 融合。这步很关键,否则各 head 之间信息不交流。

在 multi-head 中，每个 head 有各自不同的投影权重。它学到的是不同子空间的表征(有的关注语法临近，有的关注指代等)
参数量上,单头 4096 维和 64 头各 64 维的 Q/K/V 投影总参数量是一样的——切分不增加参数,只是让模型在多个低维子空间并行地学不同的关注模式。

# 2. Multi-head attention 多头注意力的目的

使用多头的主要目的是 <font color="#45ce6e">「表征多样性」</font>。单个 head 的 softmax 注意力本质上倾向于形成一个"加权平均",注意力分布往往集中在少数位置。如果只有一个 head,模型在每一层只能学一种关注模式。切成多个 head 后,每个 head 在不同的子空间里学不同的关注模式——有的盯语法邻接,有的盯长程指代,有的盯特定语义关系。这是单头无论如何调参都做不到的。换句话说, 即使并行计算不带来任何速度收益,多头依然有价值。

总结：多头是为了**让模型在多个子空间并行地学习不同的关注模式**——这里的"并行"指的是表征层面的并行(多种模式同时存在),而非计算吞吐层面的并行。计算上的并行是免费搭车的,不是设计初衷。

# 3. Multi-head 多头注意力的通俗理解

我们在考虑两个token之间的注意力关系的时候，通常只考虑了一个方面，但是我们可以从多个方面考虑两个token之间的注意力关系，比如 “是否是指代关系”，“是否颜色相似”，“是否大小相近” 等等。当我们把向量划分成多个子空间时，就可以在子空间内，按照各自的注意力模式多方面考虑。

"角度" 或注意力模式，不是指定的，是模型通过训练学习到的。子空间的注意力模式，是在训练过程中自动涌现出来的。<font color="orange">大多数 head 学到的模式，不对应人类能够命名的清晰概念</font>。

<b><u>更准确的说法是:多头提供了多个可以各自学习不同关注模式的容器, 至于每个容器最后装了什么, 是数据和优化决定的。</u></b>

> [!NOTE] 注意⚠️
> 注意力关系计算的是 "相关性/该不该关注"。而不是相似或其他关系。attention 的 $QK^T$ 算的是一个抽象的东西: 在这个子空间里,token A 该不该从 token B 取信息。这未必是"相似",很多时候恰恰是"互补"或"语法依赖"。
