# 1. Multi Head Attention, MHA 

模型会将一个 token 的 Q，K，V 向量按不同维度，划分为多个 head，每个 head 其中几个维度。

> [!example] 向量划分为多 heads 示例
> 例如，4096 维向量，分为 64 个 heads, 每个 head 64 维。那么 head_0 -> dim_0 ~ dim_63，  head 1 -> dim_64 ~ dim_127, .....

TP, Tensor Parallelism 部署，是将 token 的 heads, 平均分配给多张 GPU，每张 GPU 负责一部分的heads 的计算(主要是 attention 计算)。比如上面的例子，如果有 4 张 GPU，那么每张 GPU 负责 16 个 heads，即 GPU 0 负责 head 0～ head 15，GPU 1 负责 head 16 ~ head 31,  GPU 2 负责 head 32 ~ head 47 , GPU 3 负责 head 48 ~ head 63。

> [!tip] GPU 上的 head 数据  
> - GPU 上的 head 数据，是输入 prompt 中，完整序列(prompt + 生成 token) 每个 token 的 Q, K, V  张量(向量）的这个 head 的分量。每个 GPU 负责多个这样的 head 分量的计算。
> - 例如 prompt “who is the president ?”, 每个 GPU 上都是完整的 "who is the president?" 的每个 token 的 Q，K，V，共5组(含问号)，只不过每个 GPU 上只有自己负责的那几个 heads 的维度，比如 GPU 0 负责 head_0~ head_63, 那么它就有完整序列前 64 个 heads 的张量(向量) 
> - 每个 GPU 计算出来的都只是自己的那部分数据。最终的结果需要将每个 GPU 负责的部分组合起来，才能得到最终结果。

这样使用多头，按头数分配给不同 GPU，每个 GPU 在自己负责的 heads 上，并行的做 attention 计算，最后再把这些部分结果组合起来，形成最终结果的计算模式，叫做<font color="#45ce6e">「Multi-Head-Attention, MHA, 多头注意力机制」</font>。

上面例子中，<font color="orange">「某一层」</font>采用 64 个 head 的 MHA， TP = 4，当前已经处理了 T 个token，那么

| GPU   | 负责的 head | KV Cache 覆盖的 token |
| ----- | -------- | ------------------ |
| GPU 0 | 0 ～ 15   | 全部 T 个 token       |
| GPU 1 | 16 ~ 31  | 全部 T 个 token       |
| GPU 2 | 32 ~ 47  | 全部 T 个 token       |
| GPU 3 | 48 ~ 63  | 全部 T 个 token       |

这里的 T 包括 prompt, 以及已经送入模型完成计算生成的token。<font color="orange">每张卡都保留完整的 token 范围，但只保存其中部分 head 的 KV</font>。
# 2. Rank

常见部署是「一张 GPU 对应一个工作进程」，这个工作进程既负责「组织该 GPU 上的模型计算」，也负责发起「跨 GPU 通信」。这个进程叫做 `rank`, 我们用 rank 编号来标识这个进程的身份，例如 rank0 表示编号为 0 的进程。

TP 部署下，每张显卡负责的是自己的那部分 heads 的计算，计算出来的结果，也是局部计算结果。因此，最终需要把每张 GPU 计算出来的局部结果汇总起来，通过 All-Reduce 求和，得到最终结果，这个过程需要 GPU 间的通信，其实就是 rank 间的通信。

因为 GPU 和 rank 间通常是一对一的关系，所以我们常常用 「rank+编号 指代 GPU」，比如说 GPU 0 是 rank0。

在单台服务器环境下，GPU 与 rank 可以简单对应起来。但是在多服务器集群下，rank 号就要区分 global rank 和 local rank 了：

>- local rank:  rank 进程在本台服务器内的编号，通常用于对应本机 GPU。
>- global rank: rank 进程在整个分布式任务中的唯一编号。注意⚠️，这里的范围是该任务，并非整个物理集群。

例如，一个任务使用 2 台服务器，每台 4 张 GPU，常见的对应关系就是

| 机器  | 本机 GPU 编号 | local rank | global rank |
| --- | --------- | ---------- | ----------- |
| 第一台 | GPU 0     | 0          | 0           |
| 第一台 | GPU 1     | 1          | 1           |
| 第一台 | GPU 2     | 2          | 2           |
| 第一台 | GPU 3     | 3          | 3           |
| 第二台 | GPU 0     | 0          | 4           |
| 第二台 | GPU 1     | 1          | 5           |
| 第二台 | GPU 2     | 2          | 6           |
| 第二台 | GPU 3     | 3          | 7           |


# 3. TP 下的 QKV 权重投影

每张 GPU 上的是完整序列 Q，K，V 的部分 heads. 获得这些局部 Q K V 的方式是。<font color="orange">常见 TP 是先切分 QKV 投影权重，再由各 GPU 计算自己负责的 head 的 Q，K，V</font>。注意⚠️：不是先在一张 GPU 上算出完整 Q，K，V，再切分发给其他 GPU。

例如，MHA，64 个 head, TP = 4 为例，在<font color="#45ce6e">「某一层」</font>：
1. 加载模型时切分权重，每张 GPU 保存对应 16 个 head 的 $W_Q,W_K,W_V$
2. 计算是，每个 GPU 获得<font color="#45ce6e">「相同的输入状态 X」</font>，分别执行 
   $$
   Q_i = XW_{Q,i}, \space K_i = XW_{K,i}, \space V_i = XW_{V,i}
   $$
   其中 $i$ 表示 GPU 对应的第几个 TP 分片。 $Q_i = XW_{Q,i}$  中的 $W_{Q,i}$ 是 $W_Q$ 切分的由第 $i$ 张 GPU 负责 heads 的 $W_Q$ 投影权重的子矩阵。$W_{K,i}$ 和 $W_{V,i}$ 是同样的意义，分别是 $W_K$ 和 $W_V$ 投影权重矩阵切分的，由第 $i$ 张显卡负责的那部分 heads 的投影权重子矩阵。
3. 每张 GPU 用本地的 Q，K，V 计算自己负责的 attention head, 并把本地 K, V 写入自己的 KV Cache.
4. 各卡完成本地输出投影后，再通过 All-Reduce 通信合并部分结果。

因此，<font color="#eb4349">「QKV 从计算出来时就已经按 head 分布在不同 GPU 上了」</font>。GPU 上的投影权重矩阵，本身就是按 head 切分后的 $W_Q,W_K,W_V$。

注意⚠️：投影权重先按 TP 切分，每张 GPU 拿到的是<font color="#45ce6e">「相同的完整的输入向量」</font>，直接计算自己负责的 head 的 Q，K，V。

# 4.  单服务器与多服务器集群

在 TP 的部署下，系统以 TP 进程组中的 rank 进程为单位，常见配置下一个 rank 对应一张 GPU，服务器边界不改变基本计算逻辑单元。

也就是说，GPU 无论是否在同一台服务器上，它们在逻辑上是同等层次的，peer-to-peer。不同之处在于，服务器内的 GPU 之间的通信走的是 NvLink 或 PCIe，而跨服务器之间走的是网络，带宽差异很大。就计算逻辑来说，是以 GPU 上的计算进程 rank 为基本计算单位的，与是否在一台服务器上的关系不大。

# 5. All-Reduce

All-Reduce 是一种<font color="orange">「集合通信」</font>，把通信组内各个 rank 的数据做<font color="orange">「规约计算」</font>,  并且让每个 rank 都得到完整的规约结果。<u>规约计算可以是求和，求最大值等</u>。TP 场景下通常采用逐元素求和。

例如，4 张 GPU 各有一个向量，执行求和 All-Reduce:

| Rank | 通信的数据    | 通信后的结果     |
| ---- | -------- | ---------- |
| 0    | $[1, 2]$ | $[16, 20]$ |
| 1    | $[3, 4]$ | $[16, 20]$ |
| 2    | $[5, 6]$ | $[16, 20]$ |
| 3    | $[7, 8]$ | $[16, 20]$ |

因为 $[1,2] + [3, 4] + [5, 6] + [7,8] = [16, 20]$ . 它是把对应位置加起来，向量维度不变。把各卡的数据拼接起来，并让每张卡得到拼接结果，那是 All-Gather。

TP 做 attention 时，常见的处理过程是：
1. 每张 GPU 算出自己负责的 head 的 attention 输出 $H_i$
2. 使用本地输出投影权重，计算 $Y_i = H_iW_{O,i}$ (最后一层 attention 完成计算，输出状态后，输出的状态还要乘以一个输出投影矩阵才能得到最终输出向量)。
3. 执行求和 All-Reduce: $Y = \sum_{i}Y_i$  让所有 GPU 都得到完整的 attention 输出投影结果。

All-Reduce 描述的是最终效果，实现可以使用<font color="orange">「环形，树形等通信算法」</font>，不需要把所有数据集中到一张 GPU 上计算，再分发。

> [!tip] 关键点
> 投影后的 $Y_i$ 已经具有完整的维度，但数值只是本卡负责的 head 对最终数值的贡献，所以需要求和。
> $Y_i$ 具有完整的维度，是因为 $W_O$ 按输入维度进行切分，各卡仍保留全部的输出维度。

例如，假设模型向量的维度是 8，有 4 个 head, 每个 head 输出 2 维， TP = 2。如果不使用 TP = 2，4 个 Head 输出拼接成 8 维，再乘以输出投影矩阵
$$
\underbrace{H}_{1 \times 8} \times \underbrace{W_O}_{8 \times 8} = \underbrace{Y}_{1 \times 8}
$$

使用 TP = 2 后，每张 GPU 负责 2 个 head， 所以本地的 $H_i$ 是 4 维的，对应的 $W_O$ 按行进行切分

| GPU   | 本地 head 输出 $H_i$ | 本地权重 $W_{O,i}$ | 本地投影结果 $Y_i$ |
| ----- | ---------------- | -------------- | ------------ |
| GPU 0 | $1 \times 4$     | $4 \times 8$   | $1 \times 8$ |
| GPU 1 | $1 \times 4$     | $4 \times 8$   | $1 \times 8$ |

矩阵乘法的结果维度由权重的列数决定，因此 $(1 \times 4) \times (4 \times 8) = 1 \times 8$ 。但它不代表已经算出了完整结果，每张卡只是算出了自己负责的 head 对这 8 个输出位置的贡献。
从矩阵分块来看
$$
H = [H_0 \space H_1], W_O = \begin{bmatrix} W_{O,0}\\ W_{O,1} \end{bmatrix}
$$
因此完整的最终输出向量结果为：
$$
Y = HW_{O} = H_0W_{O,0} + H_1W_{O,1} = Y_0 + Y_1
$$
所以，$W_O$ 要按行切分。并且这就是随后需要 All-Reduce 求和的原因，各卡上的结果的形状已经完整，但是每个位置的数值还缺少其他卡的贡献。

> [!warning] 特别注意「部分贡献」
> 在做完各自 attention 计算后，经过 $W_Q$ 之前，GPU 上保留的是自己负责的那部分 heads 向量。经过 $W_Q$ 之后，$W_Q$ 把这些 heads 向量的信息混合到到完整维度的向量里。最终的完整向量里只有该 GPU 负责的这部分 heads 的贡献。注意⚠️，完整向量里的 heads 维度的部分也不是最终结果，heads 向量信息已经被 $W_Q$ 扩展或者混合到所有向量维度中。最终结果要做完 All-Reduce 之后才会得到，目前得到的完整向量只有该GPU负责heads的「部分贡献」。
> 
> 所以，<font color="#eb4349">每张 GPU 最终输出的是完整维度的向量，但是只有自己负责 heads 的贡献，只有等到做完 All-Reduce 操作之后，才能得到最终的完整向量结果。</font>


# 6. Ring All-Reduce

All-Reduce 是把每张卡的数据做「规约计算」，在 TP 场景下通常采用规约求和。上面讨论的是规约求和的算法逻辑。但是在 GPU 集群上，要实现 All-Reduce 需要节点间的「通信算法」，比如「环形通信算法」 和 「树形通信算法」。最常见的是环形通信算法，叫做<font color="#45ce6e"> 「Ring All-Reduce」</font>。

TP 会把向量分为多个 heads，GPU 会平均分配负责一部分的 head, GPU 完成 attention 计算之后，会把自己负责的计算完的 heads 向量，通过 $W_Q$ 投影矩阵，得到一个完整维度的向量。该向量包含该 GPU 负责的 heads 的贡献。每张 GPU 都输出一个包含自己贡献的完整维度的向量。然后对所有 GPU 上 Rank 进程(输出完整维度向量的计算进程)，执行求和运算才能得到最终结果。

比如 8 张卡，每张卡手里都有一部分数据 1GB，最后要每张卡人手一份总和。
![286](Pasted%20image%2020261106132020.png) ![293](Pasted%20image%2020261106132231.png)

最笨的方法就是全都发给 1 号卡，1号卡就要收 7GB 数据，再发送出去 7GB 的数据。1号卡处理的时候，其他卡都在等它。

我们换一个方法，让 8 张卡围成一个圈，每张卡只和下一张卡对话。这样每张卡只用传 1.75GB，并且卡再增加，也不会传输超过 2GB 的数据(假设每张卡有 1GB 数据)。假设有 N 张卡，需要传递的数据量为：

$$
\frac{1GB}{N} \times 2(N-1) = \frac{2(N-1)}{N} = 2 - \frac{N}{2}
$$

所以不会超过2 GB。这就是 「环型 Ring All-Reduce」算法。

All-Reduce 计算分为两个阶段一个是<font color="#45ce6e">「Reduce-Scatter」</font>, 一个是<font color="#45ce6e">「All-Gather」</font>。
## Phase 1: Reduce-Scatter

首先，现在各 GPU 的 rank 中是完整维度的向量。GPU 将完整维度的向量按照 TP 数(系统中 GPU 数量)切成数据块。例如完整向量是 256 维，有 8 张 GPU，即 TP = 8，则

| 数据块   | 包含向量的哪些维度   |
| ----- | ----------- |
| 第 1 块 | 第 1～32 维    |
| 第 2 块 | 第 33～64 维   |
| 第 3 块 | 第 65～96 维   |
| 第 4 块 | 第 97～128 维  |
| 第 5 块 | 第 129～160 维 |
| 第 6 块 | 第 161～192 维 |
| 第 7 块 | 第 193～224 维 |
| 第 8 块 | 第 225～256 维 |


> 注意1 ⚠️: 「切块」只是按位置分组，数据本身不变，也不复制。
> 注意2⚠️：这里的切块和 head 的划分是完全不同的概念，没有任何关系。head 是 TP 分别计算 attention 时的划分。这里切块是 All-Reduce 阶段，为了规约计算通信进行的划分。

8 张 GPU 都按这个相同的位置划分自己的向量。

接下来，每轮通信，每张卡往下一张卡只传送一个数据块，也就是 32 维数据。但是每轮传的块会改变， 并不是一直传固定的那一块。

每轮每张卡，都接受上一张卡传来的数据块，传过来的是哪个编号的数据块，就把这个数据块和本地相同编号的数据块相加，相加的结果就是下一轮要传递给下一轮的数据块。简单点说，就是每张卡转发上一轮收到并完成相加那一个数据块。

第一轮 8 张显卡各自选择一个不同的数据块，作为起始数据块， 8 张显卡完全错开。对于 n 张卡，接受 -> 相加 -> 转发，这样的轮次要进行 n - 1 轮，这里就是 7 轮。站在 GPU 0 的角度看，GPU 0 只会把数据传递给 GPU 1，而也会接受来自 GPU 7 的数据。

|轮次|GPU 0 发给 GPU 1|GPU 0 从 GPU 7 收到，并进行的计算|
|---|---|---|
|1|自己的第 1 块|收到第 8 块，加上自己的第 8 块|
|2|上轮算出的第 8 块部分和|收到第 7 块，加上自己的第 7 块|
|3|上轮算出的第 7 块部分和|收到第 6 块，加上自己的第 6 块|
|4|上轮算出的第 6 块部分和|收到第 5 块，加上自己的第 5 块|
|5|上轮算出的第 5 块部分和|收到第 4 块，加上自己的第 4 块|
|6|上轮算出的第 4 块部分和|收到第 3 块，加上自己的第 3 块|
|7|上轮算出的第 3 块部分和|收到第 2 块，加上自己的第 2 块，得到该块最终总和|

## Phase 2: All-Gather

接下来，再进行 n - 1 轮传递，不过这个阶段，进行传递的时候，每张显卡执行的操作，只有

```
接受 -> 存储 -> 转发
```

<font color="#eb4349">接受到数据后，不再进行相加，转发的是刚刚收到并存储的数据。</font>

一开始，每张显卡转发出去的数据，都是 Reduce-Scatter 阶段收到的最后一个数据块，它就是这个数据块的最终结果。所以，All-Gather 阶段，每张 GPU 收到的和转发给下一张 GPU 的，都是不同数据块的最终结果，每次存储一个转发一个，一个大循环 n - 1 轮后，这里是 7，每张 GPU 上都有完整维度的最终数据块。
这些数据块拼起来，就是完整的计算完 attention 的最终结果向量。

## 总结

一个完整的 TP 过程，大概分为「TP 计算」和 「All-Reduce」两个步骤。All-Reduce 又分为「Reduce-Scatter」和 「All-Gather」两步，「所以 Reduce-Scatter + All-Gather = All-Reduce」。

首先是向量按照 TP 数划分 heads，各 GPU 对负责的 heads 并行做 attention 计算，最终得到一个完整维度的结果向量，但是其中只有自己 GPU 负责 heads 的贡献。

Reduce-Scatter 让 n 张 GPU，每张 GPU 将完整向量分成 n 各数据块，各自选择一个不同的数据块作为起始数据块，n 张显卡选择的数据块全部错开。每张显卡只接受上一张显卡传过来的数据块，传过来哪个编号的数据块就和本地对应的数据块相加，并在下一轮将这个数据块传递给下一张GPU。 执行 n - 1 轮后，每张显卡上都有一个不同的数据块是这个数据块的最终结果。

All-Gather 接着 Reduce-Scatter 的最后一步，接着往下传递数据块，不同之处在于这个阶段收到上一张 GPU 传递过来的数据块之后，不再做加法，而是直接存下来，并在下一轮将它再转发出去。如此，n - 1 轮后，每张 GPU 上都有完整维度的最终结果向量。

> [!tip] 通信压力
> 对每一张 GPU 而言，Reduce-Scatter 阶段要对外发送 n - 1 次数据，要接受 n - 1 次数据。在 All-Gather 阶段要发送 n - 1 次数据，同时也要接受 n - 1 次数据。所以，对于系统中的任何一张 GPU 在做 All-Reduce 时，都要进行 2(n-1) 次发送，2(n-1)次接收。 
> - 如果系统中有 8 张 GPU, 那要 14 轮通信(14轮发送，14轮接受)，如果系统中有 16 张 GPU，那就要 30 轮通信(30轮发送， 30 轮接受)。
> - 如果系统中有 8 张卡，每张卡上的数据是 1 GB，分成 8 块后，每个数据块就是 1/8 = 0.125 GB 数据。一共通信 14 轮，所以每张显卡要发送 1.75GB数据，接受 1.75GB 数据。


> [!tip] Attention Layer
> 上面说的 All-Reduce 算法针对的是一层 Attention Layer 要做的计算。如果 Transformer 架构下有 L 层 Attention Layer, 那么每一层都要做一次 All-Reduce。因此，任意 GPU 在推理出下一个 token 的时候，都要做 L 次 All-Reduce, L x 2(n-1) 次 GPU 间发送数据通信，L x 2(n-1) 次 GPU 间接收数据通信。

这个算法，每一轮所有的卡都在收发，没有任何一张卡闲着，也没有谁被挤爆。每张卡一共只发了 2(N-1) 个数据块，接收了 2(N-1)个数据块，也就是 2(N - 1) / N 份数据。
