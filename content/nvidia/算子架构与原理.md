算子是指的一个通用的计算过程，可以被不同的部分调用。比如GEMM(通用矩阵乘法)，RoPE, 激活算子等。

但是⚠️：<font color="#45c36e">算子是一个逻辑层概念，是要被实现的逻辑规格(要算什么)，而真正算子的实现，会调用 kernel 在GPU端执行真正的运算。kernel 本身是针对某个硬件架构编写的，所以 kernel 是算子在某个具体 arch上的物理实现。因此针对不同arch的kernel实现，就形成了同一个算子针对不同arch的版本，比如 sm75, sm80等。</font>
<font color="#eb4349">算子是规格与实现分离的架构</font>

一个算子是用分层的方式来实现的。一个算子内部，分为 4 层：

>- 1. <font color="orange">算子的逻辑定义 / schema</font>——只声明"接收什么、产出什么、语义是什么",不含任何实现。这是纯抽象层 "算法逻辑"。
>- 2. <font color="orange">dispatch 层</font>——PyTorch 的 dispatcher 根据 (device=CUDA, dtype, backend…) 把这个算子调用**路由**到某个具体实现。这一层是"分层"之所以存在的关键:上层只认算子,选哪个实现是运行时决定的。
>- 3. <font color="orange">实现(implementation)</font>——可能是一段 host 侧 C++ 代码,它再去 launch 一个或多个 **kernel**;也可能直接就是一个 kernel。
>- 4. <font color="orange">kernel</font>——真正在 GPU 上跑的 SASS,针对具体 sm。

一个算子的具体调用流程如下：当我们调用一个算子的时候，比如是GEMM。调用算子是一个逻辑上的抽象概念，真正执行的时候，它会由dispatcher层将算子调用，派发或者路由给一个具体实现，上层只认算子，选哪个实现，是运行时决定。然后，实现(implementation)本质上一段C++代码，它会launch一个或多个kernel，真正在 GPU 上做计算的是kernel。kernel是针对不同硬件架构实现的，多个kernel支持不同arch, 比如 sm_75 / sm_80 / sm_86。

所以，算子是一个抽象的逻辑框架或者逻辑定义。同一个算子，可以有多个不同的实现(implementation)，每种实现可以针对这个算子的目标，采用不同的算法。实现无论采用什么算法，最终计算都要落脚到GPU设备上，这部分就是 kernel 来执行。kernel 本身是针对不同的硬件架构设计的，针对sm_75，针对sm_80 或 sm_86。每个kernel对应一种架构 arch。
我们调用一个算子时，具体使用哪个实现，是由dispacther决定的，同时该实现使用哪个kernel版本是由运行时按当时device自动选择。

> [!NOTE] Kernel 实现
在具体实现的时候，sm_80 和 sm_86 多半不是两份独立手写的kernel，而是同一份kernel源码编出的不同cubin。**一份 CUDA 源码**,里头用 `__CUDA_ARCH__` 宏处理少数差异,然后在 build 时用 `-gencode arch=compute_80,code=sm_80; arch=compute_86,code=sm_86…` 把它**编译成多个 arch 的二进制**,一起打进 wheel。

从逻辑上来讲，我们可以为同一个算子提供不同的实现，在实现里面，一个实现也对应多个不同的kernel，每个kernel对应一种arch。

<font color="#45c36e">由于大多数普通算子是框架提供算子时附带提供的唯一实现，默认绑定，是写死的算子，不可更改，且实现的大部分逻辑都是和GPU上的计算有关，即在kernel中实现，所以通常我们就把kernel说成是一个算子的实现。</font> (其实中间还有dipatcher和host实现层，不过不影响理解)

<font color="orange">比如vLLM中的attention是一个算子，而 FlashAttention, FlashInfer, XFormers, 这些都是对attention算子的实现。而每个实现，各自有kernel针对不同的arch。比如 FlashAttention 提供的kernel版本sm_80, sm_86, sm_89, 而 XFormers 提供 sm_75, sm_80, sm_85版本。</font>
