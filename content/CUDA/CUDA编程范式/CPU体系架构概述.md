# 2. CPU体系架构概述

CPU 本质上并不复杂，但是现在的 CPU 体系中加入了很多其他的东西，让它变得很复杂。

CPU：执行指令处理数据的器件。它能执行基本的逻辑和算术指令。现代CPU增加了很多复杂功能，包括内存接口(需要与内存间有大量的吞吐带宽)以及外部设备接口。还包含了大量的晶体管(百亿级别)。

# CPU 计算单元架构

#### ▪︎ 指令

CPU中执行的指令大致分为三种, 例如：

```nasm
add r3, r4 -> r4 # ① 算术指令
load [r4] -> r7  # ② 访存指令
jz end           # ③ 控制指令

```

算术指令：CPU只关注加和乘指令，除和减可以通过转换，转换为加和乘来做。① 将 r3, r4 中的值相加，将结果放在 r4 中。
访存指令：数据处理之外，也需要存储，需要读和写。②把 r4 地址中的内容读到 r7 里面。
控制指令：程序的执行需要控制，所以有控制指令。

对于一个编译好的程序，我们的优化目标就是

$$
\frac{cycles}{instruction} \times \frac{seconds}{cycle} \\ i.e. \space CPI(cyccles\space per \space instruction)  \times clock cycle 
$$

CPI 表示一个指令需要多少个时钟周期完成。clock cycle 表示每一个时钟周期需要多少时间。它们的乘积就会得到 平均意义上一条指令需要多少时间。这是优化 CPU 的目标， 尽量降低指令的平均执行时间，也就是让每条指令执行的时钟周期最少， 同时让每个时钟周期所需的时间最短。

但是 CPI 和 时钟周期，这两个指标彼此并不独立，可能降低了一个，另一个又升高了。这就催生出大量的设计，催生出各种折衷和优化。

#### ▪︎ 摩尔定律 Moore’s Law

**芯片的集成密度，每两年翻一翻，成本下降一半**。在信息产业初期，摩尔定律的表现很好，但是随着产业不断发展，摩尔定律开始力不从心，因为硅基芯片的加工工业已经逼近了物理极限。制程从28nm, 到10nm, ….等等。在 5nm 左右，量子效应已经到了非常明显的程度。现代工艺要再往下制造已经是非常困难的了。

晶体管的增长速度非常快，是指数级的增长。现在已经到了 亿/十亿/百亿 的量级。这么多的晶体管究竟是在干什么？

#### ▪︎ 流水线Pipeline

CPU 处理过程分为这几个步：Fetch(取指) —> Decode(译码) —> Execute(执行) —> Memory(访存) —> Writeback(写回). 这个过程有大量的并行性在里面。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%202.png)

CPU内部的处理，跟工厂的流水线是一样的。上面所说的CPU处理的5个步，就是流水线上的 5 个工作步骤。这几个步骤分别对应于整个数据通路和控制系统里面不同的状态。一个 a + b，在CPU系统里需要考虑存储器怎么放，该动用什么样的器件，需要调用很多资源。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%203.png)

所以，把整个过程进行切分，切分成不同的阶段，形成一个流水线。流水线利用的是指令级的并行，流水线极大减少了时钟周期，但是增加了一些延迟和芯片面积。同时，它带来了一些问题，指令具有依赖关系？以及分支怎么处理？还有一个要考虑的问题，就是流水线长度(分为多少级流水)，比如 Core 2 是14级流水，而 Pentium 4 是 > 20级流水。

#### ▪︎ 旁路 Bypassing

旁路是为了解决一些指令依赖情况下的等待问题

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%204.png)

比如，上面第二条 add 指令要依赖第一条 sub 指令做完产生 R7 的结果。但是R7的结果计算完成后，并不是一定要先做访存写入，然后再由第二条指令访存读出。在第一条指令产生 R7 结果后，我们就可以从寄存器中，将结果提供第二条指令。这个方法就叫 **Bypassing, 旁路**。具体的这里不用过多细究，只需要知道这个思路就行。

并不是所有的情况，都可以通过旁路的方式进行加速。

#### ▪︎ 分支 Branches

有时候我们需要判断，根据判断结果决定要不要执行某个循环，因此，下一条语句究竟是什么，我们还不知道。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%206.png)

在这种情况下，等待是一个最基本的处理策略。但是等待并不是一个好事，我们必须想办法出击，解决这个问题。

#### ▪︎ 分支预测 Branches Prediction

加速这个过程的的其中一个方法，就是分支预测，简单说，就是「猜」。其中，常用的一个策略就是基于分支历史的预测。具体的策略非常复杂，不做深究。

现代的分支预测器准确率都高于了90%，这能提高性能和能量效率。但是这也会带来一些开销，一个是面积增加，一个是可能会增加延迟。

#### ▪︎ 分支断定 Branches Predication

分支断定不使用分支预测器。不分析这个分支，直接把两种可能都做一遍，大小全都押。这种策略看起来很傻，但是实践中，它带来了很多优势。

首先它不需要复杂的分支预测器，减少了芯片面积。其次，由于都做，就减少了错误预测的问题。GPU中就使用了分支断定。

#### ▪︎ 提升 IPC

IPC，Instructions per cycle, 即，CPU 每个时钟周期能处理的指令数。正常常规的 CPU，一个时钟周期就完成一条指令，但是为了处理更多的数据，提出了 **超标量结构，Superscalar**。它的思路就是增加流水线的宽度。比喻来说，三头六臂的工作就是超标量的处理器。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%207.png)

图中下面的红色部分，就是增加的流水线宽度。器件多了，我们能做的工作就多了，意味着一个时钟周期，可以处理的指令就多了。

理论上讲，Superscalar的峰值 IPC 是 N (N路超标量)。实际上，它需要一些额外开销，我们需要一些技巧来逼近这个峰值。另外，它的资源使用实际上并不少，有N倍的芯片面试的增加，同时流水线之间的旁路设计，会以 $N^2$ 的量级增加，而且还需要更多的寄存器和存储器带宽。

超标量现在已经成为了很多处理器的一个标配，或者说是一个基本设计逻辑。下面是 Sandy Bridge处理器的结构逻辑图。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%208.png)

这有6个端口，port 0~port 5, 每个时钟周期可以发射 6 条指令。最上面是一个调度器，它的下面有6条流水线。

#### ▪︎ 指令调度 Scheduling

在我们的指令流里面，有一个很重要的东西，就是**指令调度，scheduling**。例如：

```nasm
xor r1, r2 -> r3
add r3, r4 -> r4
sub r5, r2 -> r3
addi r3, 1 -> r1
```

xor 与 add 相互依赖，Read-After-Write, RAW。
sub 与 addi 相互依赖，RAW
xor 与 sub 不依赖，Write-After-Write, WAW。

虽然 xor 与 sub 没有依赖关系，但是他们有顺序问题，如果 r3 在 add 中已经用完了，那没问题。如果没有用完，sub就进行了写r3的操作，那就有问题。所以，这就有一个调度问题，让代码跑得更快，但是不能有错误。这里面就用到了寄存器重命名，Register Renaming。将代码改为

```nasm
xor p1, p2 -> p6
add p6, p4 -> p7
sub p5, p2 -> p8
addi p8, 1 -> p9
```

我们对使用的寄存器进行了重命名，因此 xor 和 sub 就可以并行执行了。

#### ▪︎ 乱序执行 Out-of-Order(OoO) Execution

重排指令，以获得最大吞吐量。OoO本身会带来很多开销。Sandy Bridge 里有一个比较复杂的OoO结构

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%209.png)

乱序执行，能够让 IPC 接近理想状态，但是会导致面积增加和功能增加，因为加入了新的器件。复杂的 CPU 就比较喜欢用 OoO, 而简单的 CPU 就不喜欢用这样的方式，比如 Intel Atom(阿童木), ARM Cortex-A8 (Apple A4)就是顺序执行，而 Intel Pentium Pro，ARM Cortex- A9(Apple A5)就使用了乱序执行。主流的服务器芯片，常见的 PC 芯片，都使用了OoO。

# CPU存储器架构与并行性问题

常规计算机任务，占大头的工作是把数据搬来搬去，真正干活的时间不一定很长。主要的工作是在访问存储器。存储器特点是很慢，而且越大越慢。

|  | 延迟 | 带宽 | 大小 |
| --- | --- | --- | --- |
| SRAM (L1,L2,L3) | 1-2 ns | 200 GBps | 1-20 MB |
| DRAM (memory) | 70 ns | 20 GBps | 1-20 GB |
| Flash (disk) | 70-90 𝜇m | 200 MBps | 100 - 1000 GB |
| HDD (disk) | 10 ms | 1-150 MBps | 500 - 3000 GB |

#### 缓存 Cache

缓存的基本逻辑就是把数据放在尽可能接近处理的位置。缓存实际上利用了时间的临近性，刚刚使用过的数据，很可能被再次使用。空间的临近性，倾向于使用周围的临近数据。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%2010.png)

缓存本身也是有层次的，Cache Hierarchy，分为一级缓存，二级缓存，三级缓存。级越小，速度越快，容量越小。分级就是因为，我们无法在一个低成本下，做出非常快的大缓存。从前面 Core i7 的架构图中，我们就可以看到，仅仅是 一个 L3 缓存，就占据可芯片大量的面积。

#### CPU内部的并行性

- 指令级并行， Instruction-level parallelism(ILP) extraction. 包括超标量 Superscalar, 乱序执行 Out-of-Order。
- 数据级并行性 Data-Level Parallelism(DLP), 包括矢量计算 Vectors 或者向量计算。
    
    向量计算的数据并行就是用相同逻辑处理许多数据时，让在不同数据上的相同操作，同时去做。比如
    

```cpp
for(int i = 0; i < N; i++)
	A[i] = B[i] + C[i]
```

        这就是把 B 和 C 对应位置上的数据加起来，放到 A 对应位置上去，这个 N 可能很大。他们之间没有依赖性，操作互不干扰。

        数据并行性

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%2011.png)

我们发现每一组数据之间，没有相关性。这样的情况下，就带来并行和并行度的问题，我们可           以同时做若干组。这些数据的计算使用的是同一组指令逻辑，并且执行单元(ALU)很宽，寄存器      也很宽的时候，我们就可以并行计算。这种并行方式叫做 **单指令多数据并行(Single Instruction Multiple Data, SIMD)**。

- 线程级并行，Thread-Level Parallelism(TLP), 比如我们常见的**同步多线程 Simultaneous Multithreading(SMT)**, 以及多核 Multicore。
    
    一个线程具有指令流(Instruction streams)，私有的寄存器(Private Registers)，程序计数器(Private PC)，和栈(Stack)。 
    
    多核 Muticore 本质上，就是多个ALU流水线。之前有一些关于真多核伪多核的一些争论。其实讨论的就是是否是将流水线完整的复制，形成一个完整的核。Sandy Bridge中就是有 6个 完整的核, 除了最后一级缓存外，不共享任何其他资源。
    
    这就带来了一些新的问题，多核程序和利用率的问题。还会带来存储器里面的 锁存， 一致性(Locks)和同一性(Consistency)的问题。
    

# CPU系统的困境：能量墙 Power Wall

CPU主频的提升带来了功耗大规模的提升，功耗的增加，使得芯片的面积，成本，集成度不能无限制的增加。

![image.png](2%20CPU%E4%BD%93%E7%B3%BB%E6%9E%B6%E6%9E%84%E6%A6%82%E8%BF%B0/image%2012.png)

在05年的时候，我们预测15年时，芯片频率应该达到20GHz。而到了07年，我们悲观了点，觉得15年能达到7，8GHz，但是事实上到了 2015 年，CPU主频不升反降，还是2～3GBHz的样子。原因就是以为撞上了**能量墙 Power Wall**。

这就带来新时代的计算技术，并行计算。原因是单核处理器，遇到了物理约束，让我们无法继续保持增长。芯片的能量密度，已经接近于核反应堆的能量密度，下一阶段可能接近火箭发射口的能量密度，再下一步就要接近太阳表面了。

所以提出来一个新摩尔定律。芯片的密度和集成度增长，单核性能不会大幅提升了，它只会越来越胖，核越来越多。这时，我们就撞上另一堵墙，**存储器墙**。处理器的存储器带宽已经完全满足不了处理能力的提升，并且差距越俩越大，导致我们系统，看起来性能很好，峰值性能很高，实际使用性能惨不忍睹。

# 总结

CPU 设计逻辑是为串行程序优化的。它用了很多技术提升 CPU 的性能，包括流水线(Pipeline)，分支预测(branch prediction)，超标量(superscalar)，乱序执行(OoO)等。但是，由于缓慢的内存带宽，带来了新的方向，就是并行计算。这个方向导致了GPU系统应用于并行计算，因为它能做到成千上万的核，或说成千上万的活动线程并发执行。它才能充分发挥多核并行计算范式的优势。这就是整个 GPU 系统存在的基础。
