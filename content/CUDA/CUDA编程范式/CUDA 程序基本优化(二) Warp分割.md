# 10. CUDA程序基本优化(二): Warp分割

# Warp分割

Warp 分割，指的是在 bock 块内线程如何划分成 warp。懂得 warp 分割，可以减少「分支发散」，让 warp 尽早完工。**线程分割成Warp的原则是， 连续32个线程组成一个Warp，即线程索引threadIdx 是连续增加的一组编号**。

Block 被划分为以 32个 线程为单位的线程组或Warp组。

例如 block 内，线程 0～31 —> Warp 0,  32~63 —> Warp 1, 64~95 —> Warp3 ….

Warp 是调度的基本单元，调度器会在底层硬件上，以 Warp为单元，去发射线程指令。具体点就是在一个SMSP内，有独立的 Warp Scheduler, 它负责向 Warp 内的 32 个线程统一发射指令。

设备上的 Warp 切换是没有开销的，每个线程在程序执行期间，无论有没有被调度或者执行，它都是独占寄存器资源，直到程序结束后才释放。32个线程组成的Warp, 上下文切换的时候，只需要把Warp 的执行单元，像切换开关一样拨到另一个 Warp 上就行，下一个周期马上就可以执行另一个Warp。切换成本为 0。

一个 Warp 里面的线程同步执行相同指令，但是它们处理的是不同的数据范围，这就是 「SIMT」。虽然它们每个周期收到的指令相同，但是 Warp 里面的线程可以有自己的执行路径，分支条件不同，执行路径不同，接受到的指令可以选择执行或是不执行，这就是**「分支发散」**。

warp 分支发散的基本处理方法就是等待所有分支都完成，例如 Warp 里面，根据条件判断, 比如`if (i >5) {…} else {…}`,  一半线程执行 A 分支，一半线程执行 B 分支。

Warp 之间没有任何关系。大量的Warp在一起进行调度，可以隐藏访存的延迟。

注意⚠️，如果最后一个block的大小不是32的倍数，最后一个warp将被填充。所以我们设计block大小的时候，尽量是32的倍数。

### **并行规约优化分析**

了解 Warp 分割之后，我们再分析一下前面的两种并行规约的方式。为了分析方便，假设 warp 的大小是2。那么：

![image.png](10%20CUDA%E7%A8%8B%E5%BA%8F%E5%9F%BA%E6%9C%AC%E4%BC%98%E5%8C%96(%E4%BA%8C)%20Warp%E5%88%86%E5%89%B2/image%201.png)

处理 8 个数的规约，我们需要 8个线程，4个Warp。

第一轮：左边的方法，0～3号warp, 一开始两个线程就产生了分歧，一个要做加法，一个不做加法，就产生了分支发散，产生了4个分支发散。而右边的方法是没有分支发散的。

第二轮，左边产生2个分支发散，右边还是没有。

第三轮，左边产生一个分支发散，右边也产生一个分支发散，这是不可避免的。当剩余元素个数小于warpsize时，分支发散就不可避免。使用第二种方法，可以让一些warp尽早结束退出，释放资源。
