# 专题三：线程层次与索引

# 1. 线程层次和索引概念

CUDA 中线程的组织形式分为三层，Grid 线程网格，Block 线程块，Thread 线程。一个 Grid 里包含若干 Block，一个 Block 里包含若干 Thread。Grid 中索引 block 的方式，可以是一维索引(也就是标量编号)，二维索引(x, y)，三维索引(x, y, z)。

![image.png](%E4%B8%93%E9%A2%98%E4%B8%89%EF%BC%9A%E7%BA%BF%E7%A8%8B%E5%B1%82%E6%AC%A1%E4%B8%8E%E7%B4%A2%E5%BC%95/image.png)

我们在索引一个线程的时候，首先要在 Grid 中索引到 block， 再由 block 索引到具体的线程号。

Block 可以是一维，二维或三维的，用图形表示就是 线，面，体 或者 数组，矩阵，立方体。以二维 block 为例, x 轴 和 y 轴的方向如下所示：

![image.png](%E4%B8%93%E9%A2%98%E4%B8%89%EF%BC%9A%E7%BA%BF%E7%A8%8B%E5%B1%82%E6%AC%A1%E4%B8%8E%E7%B4%A2%E5%BC%95/image%202.png)

假设图中高亮方块代表的线程，在 block 内的索引是(x, y)。**Thread ID, 线程ID**，用变量 `thread_id` 表示，这是一个标量的标识符(编号), scalar thread identifier. 是线程的线性编号。

 `thread_id` 的计算方法就是 `thread_id = x + y * Dx` , Dx 是 block 每一行有多少线程数(x 的维度，即矩阵列数)。y 是偏移了多少行，x 是在行内偏移了多少个线程。

当使用三维 block 时，block 内的线程索引 (x, y, z) 转化为 thread_id 的计算方法就是 `thread_id = x + y * Dx + zDxDy`。DxDy 表示一层的大小，z 表示在第三维 z 坐标轴上，偏移了多少层。y 代表在一层里面偏移了多少行，x 代表在行内偏移了多少个线程。

线程索引：每个线程必须要有一个 ID (如同每个员工都必须有一个编号)，我们通过这个编号，才能定位到某个线程。一个 ID 唯一确定一个线程。ID 由几部分组成。每个线程必然隶属于某个block(如同每个员工必然隶属于某个部门)。因此线程有 block 编号，同时线程还有一个 block 内部的编号。

# 2. CUDA 内置索引变量

CUDA 对 Grid 内部索引 Block，和 Block 内部索引 Thread. 都提供了一维二维三维的索引方式，CUDA 原生支持最多不超过三维，并且 CUDA 提供了一些原生「内置索引变量」，在 kernel 启动时，CUDA 会自动设置这些内置索引变量，我们可以通过读取这些变量，获得索引信息，

| 内置变量 | 含义 | 分量 |
| --- | --- | --- |
| threadIdx | 线程在 Block 内的位置  | x, y, z 对应 `threaIdx.x`, `threadIdx.y`, `threadIdx.z` , 分别代表线程在 Block 中的 x, y, z 坐标。 |
| blcokDim | Block 在每个维度上的大小, 即在某维度上有几个线程。 | x, y, z, 假设 N * M 的二维 block, `blockDim.x` = N, `blcokDim.y` = M, `blockDim.z` = 1 |
| blockIdx | Block 在 Grid 内的位置 | x, y, z 对应 `blockIdx.x`, `blockIdx.y`, `blockIdx.z`, 分别代表Block 在 Grid 中的 x, y, z 坐标。  |
| gridDim | Grid 在每个维度上的大小，即在某维度上有几个 block。 | x, y, z。假设 N * M 的二维 Grid, `gridDim.x` = N, `gridDim.y` = M, `gridDim.z` = 1 |

CUDA 核心提供的内置索引变量就是 `threadIdx`, `blockDim`, `blockIdx`, `gridDim` 这四个变量，它们本质上都是一个结构体，有 x, y, z 三个成员变量，保留了维度信息，可以通过 x, y, z 来访问各个维度分量上的值。`threadIdx` 和 `blockIdx` 存放的是索引信息，它们是 `uint3` 结构体类型的。`blockDim` 和 `gridDim` 存放的是维度大小信息，它们是 `dim3` 结构体类型的。

未使用的维度大小为1，索引为0. 例如二维 block 的 `threadIdx.z` = 0, `blockDim.z` = 1。通过 `threadIdx` 我们可以拿到线程在 block 中每个维度上的坐标, `blockDim` 可以拿到每个 block 在各个维度上的大小。同样，通过 `blockIdx`，可以拿到 block 在 Grid 中每个维度上的坐标。通过 gridDim 可以拿到 grid 在各个维度上的大小。 

例如，假设一个 Grid 中只含有一个 Block, Block 大小 N * N, 采用二维索引：

```c
// kernel definition
__global__ void MatAdd(float A[N][N], float B[N][N], float C[N][N]){
	int i = threadIdx.x;
	int j = threadIdx.y;
	C[i][j] = A[i][j] + B[i][j];
}

int main(){
	...
	// kernel invocation with one block of N * N * 1 threads
	int numBlocks = 1;
	dim3 threadsPerBlock(N, N);
	MatAdd<<<numBlocks, threadsPerBlock>>>(A, B, C);
}
```

A, B, C 都是 N * N 的方阵，我们希望把 A 和 B 的对应位置加起来，放到 C 的对应位置上。我们假设有足够多的线程，每一个线程处理一对数据相加(类似于每个员工去搬一块砖)。

每个线程执行的指令是一样的。所有线程共享`MatAdd`函数这段代码，执行同一段指令流。不过处理数据不同。每个线程处理的数据范围，是通过自己线程编号来划分的。

每个线程的编号对应与它要处理的数据范围。一个线程处理一组相加，因此线程在二维 block 中的坐标，就直接对应于要处理元素在矩阵中的坐标。即，block 中坐标为(i, j)的线程, 处理的就是 C[ i ][ j ] = A[ i ][ j ] + B[ i ][ j ] 。通过 `threadIdx.x` 和 `threadIdx.y`  拿到线程在 block 内的坐标。

启动 kernel 时，在 Grid 里创建 1 个block, block 含有 N * N 个线程，采用二维索引。 把线程在 block 中的二维坐标，对应到矩阵 A 和 B 在该坐标上的元素。该线程的工作，就是把他们取出来相加，再放到 C 对应的坐标位置上去。

`MatAdd<<<numBlocks, threadsPerBlock>>>(A, B, C)`，意思是 kernel 启动的时候，Grid 的构建方式是，构建 numBlocks (这里是1个) 个 block，同时，每个 block 包含  `threadsPerBlock` (这里是 N * N)个线程。变量 `threadsPerBlock` 是一个 N * N 的 dim3 类型的变量。所以这是一个二维block。

<aside>
💡

dim3 threadsPerBlock(N, N)

这行代码用于指定线程块维度，它与传统的 C 语言语法不同，是 CUDA的扩展部分。

dim3 是 CUDA提供的一个结构体，用于表示三维空间的维度，通常用于定义线程块和网格的维度。dim3 结构体包括 3 个成员，x, y, z,分别表示三维空间中的三个维度。在定义时，可以指定一个，两个或三个维度的值。**未指定的维度默认为1**。

threadPerBlock(N, N), 这里的 threadPerBlock 是一个结构体变量，类型为dim3。其中 x 和 y 维度的大小均为 N，z 维度大小默认为1。例如，ThreadPerBlock(16, 16)表示，每个线程块是一个 16 * 16 的二维线程组，共 256 个。

</aside>

变量 `threadsPerBlock` 是将 block 内部的线程索引建立成一个二维索引，几行几列，不仅是一个标量编号。这样的好处就是处理二维数据或矩阵的时候，可以很方便的对应到二维数组的下标索引。因此，**「内置的变量 threadIdx 就可以获得线程的二维索引」**，然后把这种索引方式直接用在数组下标中去，直接处理对应数据。

建立索引的时候，是根据要并行计算任务的特点，来建立索引方式，一维二维三维都有可能，主要是方便 Thread 或 CUDA Core 和处理数据之间的对应关系和索引。

<aside>
💡

注意⚠️：所有线程都是共享指令流

核函数是每个线程都要同时执行的代码，MatAdd 函数是会在每一个 cuda 核的线程上完整执行。每个线程，都会首先通过内置索引变量 threadIdx 获得自己的线程编号。如果是二维索引，我们就可以获得线程的 x 和 y 坐标。然后再用这个坐标去索引对应位置上的数组元素，对相应位置上的数据进行操作。

**注意，kernel 是每个线程都要做的工作，是每个 cuda 核或线程都要执行的完整逻辑。**

</aside>

主机端 main 函数启动核函数，使用 1 个线程块，这个线程块内的线程索引是二维的，块内 N * N 个线程。按照这种方式启动 kernel 函数后，通过内置 ThreadIdx 变量，就可以获得线程的二维索引。这个索引就可以直接用在数组下标里，就可以去处理对应的数据。

# 3. 线程块索引

每个Block在 Grid 内的位置也有索引，叫**「块索引,blockIdx」**。(部门在公司里的位置) 它也是有一维二维三维的下标。块索引对应的内置索引变量就是 `blockIdx`(block 在 Grid 中的位置坐标)和 `blockDim` (Grid 中 block 在各个维度上的大小，保留的是维度信息)。

比如 每个 Block 线程块有 10 * 10 个线程，那么 blockDim 就是 10 * 10， 即 blockDim.x = 10, blockDim.y = 10。

(例如：每个部门有100人，如果整个公司有10个部门，就意味着有1000人，但是我们要找到第 3 个部门中的第 5 个人在整个公司的位置或编号，那么我们就需要知道一个部门有100人的信息，第 3 个部门第5个人，就是 3 *100 + 5 = 305， 他在整个公司的位置或编号就是305。索引从0开始)。

使用多个 block 组织线程时，如果处理二维矩阵，线程就会是「二维Grid + 二维 block」的情况，这种情况下，我们需要获得线程全局的 x 坐标 和 y 坐标，去对应到矩阵上的元素位置。在计算时需要作多级的索引转换， 即先用blockIdx 索引 block 在 Grid 中的位置，再用 threadIdx 索引 thread 在 block 中的位置。并且，x 坐标 和 y 坐标是分别进行多级索引。

```cpp
// Kernel definition
__global__ void MatAdd(float A[N][N], float B[N][N], float C[N][N]){
		int i = blockIdx.x * BlockDim.x + threadIdx.x;
		int j = blockIdx.y * BlockDim.y + threadIdx.y;
		if(i < N && j < N)
			c[i][j] = A[i][j] + B[i][j] 
}

int main(){
		...
		//Kernel invocation
		dim3 threadsPerBlock(16,16);
		dim3 numBlocks(N / threadsPerBlock.x, N / threadsPerBlock.y);
		MatAdd<<<numBlocks, threadsPerBlock>>>(A, B, C);
}
```

假设有 N * N 的方阵，用线程处理。如果使用 16 * 16 的线程块大小，就需要 `N / threadsPerBlock.x * N / threadsPerBlock.y` 这么多个block。

**线程块的数目，以及线程块中线程的数目，都是通过二维的 dim3 变量指定的**。block中的线程建立的是二维索引，threadIdx. 而 Grid 中的 block，也是建立的二维的索引， blockIdx。 

# 4. 线程索引计算

<aside>
💡

**线程位置与矩阵元素的对应处理关系**

在核函数 MatAdd 中，首先要找到线程在全局位置，对应于矩阵二维数组的下标，线程全局就是二维索引，让线程位置的 x 分量对应矩阵二维数组的行编号 i ，以及 y 分量对应矩阵二维数组的列编号 j。这样获得线程所要处理数据的位置。 即将本线程在全局线程中，x位置和y位置，直接对应到矩阵的数据元素[i, j] 上进行处理。 

</aside>

例如，假设 N = 32。对于每一个线程块的编号，都会进行下标的处理，如果每个块有 16 * 16 个线程，注意⚠️这和 N 的大小无关。对于线程块内的线程编号或下标，x 方向就是 0～15， y 方向也是 0～15，即内置索引变量为，**threadIdx([0,15], [0, 15])**。如果 Grid 里面有 2 * 2 个线程块，线程块的编号或下标，x 方向就是 0～1， y方向也是 0～1，内置索引变量为 **blockIdx([0,1], [0, 1])**。而内置变量 **blockDim 就是 16 * 16**, 它也是按二维描述的，blockDim.x = 16, blockDim.y = 16。

因此，计算一个线程全局位置坐标的方式是

```cpp
int i = blockIdx.x * BlockDim.x + threadIdx.x;
int j = blockIdx.y * BlockDim.y + threadIdx.y;
```

注意⚠️，Grid 分为了多个 block，block 又分为了多个 thread. 这里是计算的 i, j 就是，把所有block 按 Grid 布局拼起来后，线程在整个二维线程区域中的全局 x, y 坐标。它是 x, y 坐标分别计算的。

# 5. 线程约束

对于线程，GPU是有一定的限制。对于 G80 和 GT200 而言，每个线程块里面不能超过 512 个线程。对于 Fermi 架构，每个线程块不能超过1024个线程。
**CUDA Toolkit 里面，每一个特定架构里面，能够支持的每个Block里的线程数，都有特定线制**。

一个线程块中的线程，执行过程位于相同的处理器核心，也就是位于相同的SM上。不会出现一个block 中的线程，在不同的 SM 上执行的情况。

一个 block 内的线程共享所在的核(SM)分配给该 block 的 shared memory。

# 6.索引结构总结

CUDA 中的线程层次有 Grid,  Block, Thread 三个层次。我们每启动一次 kernel，就会产生一个Grid，一个Grid中，有多个block, 一个block中有多个线程Thread。

调用核函数的 kernel<<<nB， nT>>>(args…)，尖括号中的内容被称为**执行配置**，它一共有4个参数，先关注前面两个:

- 第一个(nb)是 Dimension of Grid，即它设置一个 Grid 中有多少block，即 nB, number of blocks。
- 第二个参数(nT)是Dimension of Block，是设置一个 block 中有多少线程，即nT, number of threads。例如kernelFunc<<<4. 8>>>(), 表示启动一个具有4个block的Grid，每个block有8个线程，一共启动 4 * 8 = 32 个线程。注意⚠️，nB 和 nT 可以按照一维，二维，三维…来指定。

CUDA为我们提供了内置变量，主要是两个**Dim (gridDim 和 blockDim)** 和 **两个index (blockidx 和 threadidx)**

> **gridDim**: 一个Grid中有多少个block。它也可以按照一维，二维，三维…等描述。
**blockDim**：一个block中有多少个线程。它也可以按照一维，二维，三维…等描述。
**blockIdx**：它表示当前线程所属的block，在Grid中的编号。同一个block中的所有线程，都是共享同一个BlockIdx(block编号)。
**threadidx**：它表示当前线程在当前block中的编号。
> 

如果我们打印 blockIdx 和 ThreadIdx，会发现线程的 blockIdx 可能相同(在同一个block中)，threadIdx 也可能相同(在不同block中)。说明，**本质上其实 blockIdx 和 threadIdx 都是内部编号。blockIdx是Grid内部对block的编号，threadIdx 是 block 内部对 thread的编号**。

所以，不同block下的线程ThreadIdx是会重复的，单纯通过一个threadIdx，是没有办法在全局情况下去确认一个线程的。但是我们可以通过blockDim, blockIdx, threadIdx 的换算，得到线程的全局唯一编号。如，

```c
int i = threadIdx.x + blockDim.x * blockIdx.x;//得到线程在x分量上的全局编号
int j = threadIdx.x + blockDim.x * blockIdx.x;//得到线程在y分量上的全局编号
```

## 索引深度理解

我们在程序中使用的 Grid 和 Block 的一维索引，二维索引，三维索引都是「逻辑索引」。CUDA提供了两个 Dim (`gridDim`, `blockDim`) 和两个 Index (`blockIdx`, `threadIdx`) 的内置变量。我们可以根据这些内置变量，**按需计算出一维，二维，三维坐标，或者局部、全局标量编号**。它只是逻辑索引，是我们为了将线程和它要处理的数据，对应起来，方便映射而使用的逻辑索引。

**在硬件层面，真正调度执行的时候，它会按照自己的另一套规则定位线程**。而我们上面讨论的Grid, Block，一维二维三维索引，局部/全局标量编号等，都是为了在程序层面方便，方便指定数据和线程之间的对应关系使用的逻辑概念。

但是硬件层面 和 程序层面的索引并不是毫无关联，它们存在一定的映射关系。比如，一个block 放到一个SM上执行，block 内的 warp 分散到 SMSP(SM内子分区)上执行，一个 block 独享一块 Shared Memory, 一个 warp 被一个SMSP的 warp scheduler 调度，独享一个寄存器组。

这种对应关系，CUDA自己会处理，我们只需要把程序层面的索引维护正确就行。
