#### 并行计算

并行计算，简单说就是「同时使用多个计算资源解决一个计算问题」。它涉及多个资源或处理器。问题被分解成多个离散部分，可以同时处理(并行)，每一部分由一系列指令完成。每个部分的指令在不同的处理器上执行：

![image.png](3%20%E5%B9%B6%E8%A1%8C%E7%A8%8B%E5%BA%8F%E8%AE%BE%E8%AE%A1%E6%A6%82%E8%BF%B0/image%206.png)

把问题切分成多个可以并行的多个小问题，切分方式有多种，可以是「数据切分」，也可以是「处理过程的切分」，或者都考虑进行切分。

# 概念与名词

### **Flynn 矩阵**

Flynn 矩阵是根据指令和数据，来进行整个处理模式的划分

| SISD Single Instruction, Single Data | SIMD Single Instruction, Multiple Data |
| --- | --- |
| MISD Multiple Instruction, Single Data | MIMD Multiple Instruction, Multiple Data |

SISD, 单指令单数据: 就是基本的串行模式，指令流是单一的，处理的数据对象也是单一的。

SIMD, 单指令多数据: 指令都是一样的，但是同一个指令要处理不同的数据，比如搬砖，都是搬砖的指令，但是大家要搬的砖不一样。这就是单指令多数据。

MISD, 多指令单数据: 一个数据，会有多个指令的操作过程。比如搬桌子，多个人一起去搬。

MIMD, 多指令多数据。多个指令同时作用在多个数据上。

MISD 和 MIMD 两种形式都是在研究领域有一些使用. **「并行计算领域，SIMD是最常见的方式」**。

### 基本技术概念

**Task 任务**：可以完整得到一个结果的一段程序。可以理解为一个或多个程序代码段。

**Parallel Task，并行任务**: 可以由并行计算方式去解决的一个任务。

**shared memory 共享存储**: 指令要处理相关数据，这些数据要存储在一个地方，这是大家共同享有的地方。不管是 SIMD, MISD, 还是 MIMD, 并行任务都要到一个地方去读数据或写结果。这里的共享存储，是指这些并行任务要共享的存储区域。

**Distributed Memory 分布式存储**: 指令要处理的数据，分开存储在多个地方。

**communication 通信**:  我们并行计算的单元，需要一些相互交互的信息。

**synchronization 同步**：对于一个并行系统而言，多个或若干个并行执行的代码段之间具有一致性的关系。注意，同步是破坏了并行系统的并行性的，会导致性能一定程度的下降。

**Granularity 粒度**: 并行计算在任务划分的时候，每个任务的大小。

**Observed Speedup 加速比** :   对比一个标志物，标志程序，并行系统能够获得的实际的性能提升。加速比，通常是「对相同层次的计算系统的比较」。

**Parallel Overhead: 并行开销**：一般并行系统里面，为了完成并行计算，必然有一些开销，比如进程间通信，同步等。并行开销里面，最核心的问题是通信，这和 I/O 也是结合的，因为通信经常涉及将数据从一个地方搬到另一个地方。  

**Scalability 可扩展性**：对于一个比较大的并行系统，比较强调它的可扩展性。比如在一个四核系统上，或者 4 并行度系统上，进行并行计算，如果把它扩展到 400 个核系统，那么我们可以获得的加速比是否可以线性增长，我们的效率是否可以保持较高水平，这就是可扩展性。如果设计的时候，可扩展性比较差，就会妨碍系统的提升。可扩展性主要考虑系统开销，通信，同步，交互，随着系统规模的增大，都会显著增加。

### **存储器架构**

Shared Memory / Distributed Memory / Hybrid Distributed Memory

共享存储就是有一堆砖，都堆在同一个地方，大家都去那里搬。分布式存储，就是砖分了若干堆，一个人或若干人去搬其中某个堆。存储系统中一个非常重要的点就是编址，共享存储和分布式存储，以及混合存储系统，它们的编址方式都有所不同。

### **并行编程模型**

共享存储模型 Shared Memory Model:  所有需要处理的数据都放在一个共享存储器里面，所有的处理单元，都去共享存储器里面取数据，来进行处理。当存储器面对的处理单元很多的时候，存储系统的压力就会比较大，存储器带宽可能成为瓶颈。所以共享存储模型里面，存储器的设计会非常昂贵。(多个并行处理单元会竞争访问存储器)

线程模型 Threads Model：启动很多线程，线程之间有切换，每个线程有自己独立管理的数据。

消息传递模型 Message Passing Model：在彼此独立的处理单元上，存储空间不是统一编址的，相互独立。处理单元之间的数据传递，通过消息模式进行传递。或者通过消息模式，传递控制信号。

数据并行模型 Data Parallel Model: 把数据进行了切分，让不同处理单元分别进行处理。

这些并行编程模型，并不是排他的，在一定程度上都可以进行混合。

### **Amdahl’s Law**

程序可能的加速比，取决于可以被并行化的部分。

$$
Speedup = \frac{1}{1-P}
$$

P 是可以被并行化的部分，1代表整个程序，1-P就是并行化之后剩余的部分。这两部分相除我们就得到了能够获得的加速比。如果没有可以并行化的部分，P = 0， 加速比 speedup = 1, 即没有加速。如果所有的代码都可以并行化，P = 1，那么我可以获得的加速比，理论上就是无穷大。如果50%可以并行化，那么可以获得的加速比就是 speedup = 2.

如果程序中有 N 个处理器可以并行处理，可以理解为 P 里面可以被加速 N 倍。

$$
Speedup = \frac{1}{\frac{P}{N} + s}
$$

P = 并行部分，N = 处理器数目，S = 串行部分。

并行化有一个可扩展极限的问题。假设分别 P = 0.5，P = 0.9，P = 0.99 时(50%, 90%, 99% 可并行化程度)。

![image.png](3%20%E5%B9%B6%E8%A1%8C%E7%A8%8B%E5%BA%8F%E8%AE%BE%E8%AE%A1%E6%A6%82%E8%BF%B0/image%207.png)

即使处理单元不断增加到 10000 个，问题的可并行程度为 0.5 时，我们能够获得的加速比上限就是1.99 倍。可并行化部分90%的话，无论我们多努力能够获得的加速比上限就是9.91倍。99%的话，加速比上限就是99.02倍。所以可扩展性是有一个极限的，它受制于可以并行化部分的多少。
