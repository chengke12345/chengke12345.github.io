# 算力技术指标

# 1. GPU计算任务

GPU 执行的计算任务一般分为三种类型，第一种是「哈希运算，Hashrate」, 第二种是「浮点数运算，FLOPS」, 第三种是「张量计算，Tensor」.

- 「哈希运算」：哈希计算主要用在密码学领域，用于加密和解密运算。比特币挖矿，就是使用哈希计算，去计算出一个哈希值。哈希计算的度量单位是 H/s, 即每秒执行哈希计算的次数，也叫做哈希率。在比特币挖矿领域所提到的「算力」，就是「哈希率， Hashrate」。
- 「浮点运算」：浮点运算是 AI 领域进行训练和推理时主要的计算模式，是 AI 领域的算力单位。浮点数按使用的位宽或表示范围，分为单精度浮点数 FP32，双精度浮点数 FP64，半精度浮点数 FP16。
- 「张量计算」：张量计算需要特殊的 GPU 架构。架构设计主要是针对张量之间的运算进行加速。这是深度学习执行梯度下降算法时候的加速运算能力。它的计量单位是 T/s, 表示 Tensor/s，即每秒执行张量计算次数。

# 2. 算力单位

「FLOPS」：Floating Point Operations Per Second. 每秒浮点运算次数，它用来衡量计算机或硬件的浮点数计算能力，即平时所说的「算力」。FLOPS 是算力的基本计量单位，即 「次/秒」。

在计算次数的描述中：

| 单位 | 换算 / FLOPS (次/秒) |
| --- | --- |
| MFLOPS (Million) | 1 MFPLOS = 100 万次浮点数计算/秒 |
| GFLOPS (Giga) | 1 GFLOPS = 1000 MFLOPS |
| TFLOPS (Tera) | 1 TFLOPS = 1000 GFLOPS |
| PFLOPS (Pera) | 1 PFLOPS = 1000 TFLOPS |
| EFLOPS (Extra) | 1 EFLOPS = 1000 PFLOPS |

注：在计算能力的计量上，单位是以 1000 为一个进制，与存储大小以 1024 为单位进制不同。计算中 M 代表百万次计算，而在存储中表示 「兆」字节，即 1024 字节。
目前使用最多的算力单位是 PFLOPS， 1 PFLOPS = 1000 TFLOPS, 即 $1 \times 10^{15}$ 次浮点数运算/秒。

# 3. 数据格式/精度

AI 领域在考虑 GPU 算力时，一般都考虑浮点数算力。GPU 使用不同的数据宽度的浮点数来进行运算。不同数据宽度的浮点数，就是不同「数据类型」或者「数据格式」，即 「dtype」。它本质上描述的是，用不同宽度的浮点数类型。

## ◼︎FP16 / FP32 / FP64

不同宽度的浮点数类型，可以表示的范围和精度都不同。在描述浮点数的精度时，我们采用了 C/C++ 中对浮点数分类的术语。现在最典型的 C/C++ 编译器中，float 类型是 32 位，double 类型是 64 位。

在 GPU 计算中，我们把 32位浮点数的数据格式或类型，称为「单精度浮点数」，记为 「FP32」。把 64 位浮点数的数据格式或类型，称为「双精度浮点数」，记为「FP64」。除此之外，GPU 还可能采用更小的浮点数格式，「FP16」，我们称之为「半精度浮点数」。

FP16 / FP32 / FP64 是最传统、最常见的三种数据格式。为了提高 AI 的训练和推理效率，工程实践中，我们也会根据任务采用效率更高的数据格式。比如 BP16, FP8, INT4, INT8, TF32 … 等等。

## ◼︎BF16

BF16, Brain Floating Point 16，是 Google 专门为深度学习设计的 16 位浮点数格式。现在逐渐成为了大语言模型训练使用数据格式的事实标准。 

FP16 和 BF16，都是使用 16 位 bit 表示一个浮点数，但是它们划分指数和尾数的分配不同。这就带来了动态范围和精度之间的权衡选择。BF16  具有与 FP32 相同的数据动态表示范围，但是 BF16 具有较低的表示精度。 FP16 具有缩水的动态范围，但是他具有中等精度。即：

```
BF16 = FP32动态范围 + 更低的精度
FP16 = 缩水的动态范围 + 中等精度
```

所以，BF16 更像是介于 FP32 和 FP16 之间的一个数据格式。它用 16 位表示了 FP32 的动态范围，但是牺牲了数据精度，弥补了 FP16 表示范围太小的缺陷。

BF16 缩短了数据长度，而不影响表示范围，但是丢失了部分精度，这是工程上的取舍。

<aside>
💡

FP16 的缺陷

FP16 在大模型训练中，有个臭名昭著的问题，「梯度下溢, underflow」。反向传播算出的梯度经常出现很小的数值，在 FP16 数据的最小正规数之下，变成 0，这部分梯度信息就损失了，训练发散或不收敛。早期采用的应对方案是 Loss scaling。

BF16 就直接绕开了这个问题，它的动态范围和 FP32 一致，1e-30 这种小数值可以正常表示。它在16位上的动态范围更大了，代价是精度更差，但是深度学习对精度的容忍比对动态范围的容忍要高得多，精度少几位影响不大。

</aside>

## ◼︎其他数据格式

其他会使用到的数据格式包括，TF32， FP8，INT8， INT4 等。

TF32：Tensor Float 32, 由 A100 GPU 引入的数据格式，19位实际精度，兼容 FP32 接口。

FP8:  由 H100 引入的量化推理时使用的数据格式

INT8/INT4: 量化格式

<aside>
💡

量化格式

由于大模型参数越来越大，权重参数占用显存越来越多，需要 GPU 越来越多，为了压缩模型大小，让其在更少的 GPU 上能够部署。可以把模型的参数用精度更低的数据格式来存储，因为精度对于参数量巨大的模型，影响没那么大。这样可以大量压缩模型权重参数需要占用的空间。 

</aside>

注意⚠️: 在训练，推理(未量化)，推理(量化)时，我们说的算力，都是指Tensor Core下的稠密算力dense, 而不是稀疏算力

# 4. Tensor Core

「Tensor Core」 是 NVIDIA GPU 芯片中的「专用矩阵计算单元」。「Tensor Core」 与传统的 「CUDA Core」并列存在于 GPU 芯片的 SM(Stream Multiprocessor) 中。 

「FMA」：Fused Multiply-Add, 中文翻译为「融合加乘运算」。FMA 是一条融合指令，在 CUDA Core 的一个时钟周期内可以同时发起一次包含乘法和加法的运算操作，或者说是一次乘加计算。但是 GPU 在统计计算时，会将其统计为两次浮点数运算。它是一种提升性能与精度的硬件设计。

「CUDA Core」 在每个时钟周期内执行一次标量计算，比如一次 FP32 的乘加(FMA, Fused Multiply-Add), `d = a * b + c`。

「Tensor Core」在每个时钟周期内执行一次小矩阵的乘加计算，比如 4 x 4 的矩阵， `D = A * B + C`， Tensor Core 一条指令就完成小矩阵一次乘加，相当于把 SIMD 从向量扩展至矩阵层面。

深度学习里面，最核心的计算，就是 「**GEMM(General Matrix Multiply), 通用矩阵乘法」**Transformer 里面的 $Q \times K^T$ 运算，attention output 投影，FFN 的两次线性变换，都是矩阵乘法。把矩阵想乘做成专用硬件，比单纯用 CUDA Core 的吞吐量高一个等级。

## ◼︎FP16 Tensor Core

FP16 Tensor Core 指的是 Tensor Core 在 FP16 精度下的算力。

详细的说，如果我们看到 Spec 里写到 *FP16 Tensor Core: 312 TFPLOS*,  意思就是：用 Tensor Core 硬件单元，以 FP16作为数据格式输入数据运算时，峰值算力的吞吐量能达到 312 万亿次浮点运算每秒。

「混合精度训练，AMP」:  Tensor Core 的乘加通常是混合精度，即 FP16 输入做乘法，但是以 FP32 做累加，最后的输出数据格式可以选择 FP16 或者 FP32。这样，享受了 FP16 带来的显存优势和速度，又避免了长链累加的精度损失。这就是混合精度训练 AMP，不丢失精度的情况下，可以加速 2-3 倍。

## ◼︎主流算力规模计算

现在主流表达的算力规模，指的就是 「FP16 Tensor Core」 或者「BP16 Tensor Core」，而不是裸的 FP16 或 BP16。

因为，做 AI 不可能不用 Tensor Core.

任何主流深度学习框架 (PyTorch 或 TensorFlow)，在 GPU 上做 GEMM， 默认都是走 cuBLAS / cuDNN, 这些库在 sm_70 (Volta) 以上的硬件编译版本上，都会自动调用 Tensor Core。训练用的 AMP，推理用的 vLLM, TensorRT, 底层 kernel 全是 Tensor Core 实现。CUDA Core FP16 算力对 AI 工程师来说，基本是“用不到的数字”，想用都不行，框架不允许走那条路。

所以在 AI 领域，我们说的算力通常指的就是 Tensor Core 算力。CUDA Core 算力几乎没人用。

# 5. 稀疏算力与稠密算力

在 NVIDIA 的官方文档中，我们经常看到「FP16 Tensor Core *」, 其中的 `*`  就代表这里说的是「稀疏算力 Sparsity」。没有任何标志的时候，就表示「稠密算力 Density」。因此，我们讨论 Tensor Core 算力的时候还要区分是「稀疏(Sparse)」还是「稠密(Dense)」。

NVIDIA Tensor Core 的稀疏算力是由 A100 (Ampere 架构) 引入的硬件特性，它是结构化 2 : 4 稀疏

## 稀疏矩阵(Sparse Matrix)

 「稀疏矩阵, Sparse Matrix」是指零元素占比很高，非零元素相对较少的矩阵。反之，非零元素占比较高的矩阵叫做「稠密矩阵, Dense Matrix」。

至于零元素占多少才算稀疏，没有统一的硬性阈值，取决于应用场景，以及能否通过只存储和处理非零元素来节省空间和计算。

普通稀疏矩阵不要求 0 出现在特定位置。额外要求 0 的分布要满足某种规则时，叫做「结构化稀疏」。

## 稀疏算力

我们在讨论 NVIDIA Tensor Core 规格表中的稀疏算力的时候，通常指的是 「结构化2 : 4 稀疏对应的峰值算力」。

<aside>
💡

### 结构化 2:4 稀疏

它要求的规则很具体，它要求权重矩阵中，每连续 4 个元素里，就必须有 2 个 0。

> 硬件可以加速的前提条件是，它需要一种规则，通过这个规则可以预测矩阵的稀疏模式，只有这样，硬件才能加速。结构化 2:4 稀疏，就是这个规则
> 

Tensor Core 内部有一个压缩格式，每 4 个元素，可以压缩成 2 个非零值 + 1 个 2-bit 索引 (2-bit 索引标记非零值在原来 4 个元素中的哪两个)。

> 做计算时
① 权重矩阵从 4x 个值压缩到 2x 个值 ，显存带宽减半
② 乘加只对两个非零值做运算，算力翻倍。
③ 2-bit 索引用来从输入激活中 “挑选” 对应位置的元素。
> 
</aside>

所以，在 H100 的 Spec 里，我们会看到 FP16 Tensor Core, 989 TFLOPS 的算力，FP16 Tensor Core * ，1979 TFLOPS 的算力。就是因为理论上，Tensor Core 硬件层面上，理论可以提供 Sparsity 最大 2x 的稀疏加速，这就是按结构化 2 : 4 稀疏的峰值算力来算的。
这就是 Tensor Core * 稀疏算力通常是 Tensor Core 稠密算力两倍的原因。

<aside>
💡

注意⚠️：实际工程中，结构化稀疏用得很少。

大模型的推理瓶颈往往在显存带宽和 KV Cache，而不在权重计算密度上，这样的收益不够诱人。而且剪枝到 2:4 通常会掉点，需要稀疏感知微调，来恢复精度。

我们在 NVIDIA GPU Spec 中看到的 Sparsity 的算力，往往是一个理论上限值。Dense 那一栏表示的稠密算力，才是实际工程中真正应该参考的值。

</aside>

<aside>
💡

H100 与 H200 之间在算力指标上，几乎一模一样。区别主要在三方面：

> ① H200 是 141 GB的显存，而 H100 是 80GB/94GB。
② H200 的显存使用 HBM3e 带宽是 4.8 TB/s, 而 H100 是 HBM3, 带宽 3.35 TB/s
③ SXM版本的功耗墙是都是700W，但是 PCIe / NVL 版本功耗墙是 400W。
> 

H200 相对于 H100 ，主要的升级是在显存的容量和带宽上。在 LLM 推理时，大参数的模型通常的瓶颈是在显存和显存带宽上，而不是在算力上。所以同样，Llama 270B 的模型，同样的部署方案，H200 要比 H100 快 1.9 倍。

算力是瓶颈显存够用的时候，选择 H100 更划算，它通常用于训练中小模型。而 H200 是用在算力够用，显存吃紧时，LLM 推理大概率是这种场景。

这也反应出一个行业判断，大模型时代，算力够了，memory wall 才是心瓶颈。

</aside>

<aside>
💡

B200 与 B300 在算力指标上，同样大体相同，但是在 B300 和 B200 相比，在架构取舍上进行了不少优化。

INT8 Tensor Core 和 FP64 的计算能力上，B300 直接砍掉不少，这是做的架构取舍。B300 的定位更侧重于大模型的使用，即推理场景。因此，不仅在显存上增加了接近一倍，还在 GPU 架构上进行了进一步的优化取舍。

</aside>
