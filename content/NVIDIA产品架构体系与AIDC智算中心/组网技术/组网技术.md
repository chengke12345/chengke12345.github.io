# 组网技术

算力中心的规划，主要是计算，网络，存储，三大部分。GPU 到 GPU，GPU到存储的互连，网络规划的合理性和性能直接决定了集群能否发挥出最优的表现。网络规划方面，算力中心有更高的要求

| 编号 | 类别 | 传统数据中心 | 新型算力中心 |
| --- | --- | --- | --- |
| 1 | 网络带宽 | 10-100Gb (万兆) 为主，很少配200Gb 以上网卡。 | 普遍200-400Gb 网络，800Gb 网络也在路上。AI大规模训练有海量数据传输要求 |
| 2 | 组网规模 | 集群内服务器数量低(20-30台)，每台服务器的网卡数量少(1-2块)。 | 动辄64，128台(千卡)设备，每台设备配置8-10块网卡，对交换机的数量需求激增 |
| 3 | 网络拓扑 | 通常是核心，汇聚，接入三层架构。除 HPC 高性能集群应用外，上下行网络普遍存在收敛。(上行<下行) | 以 IB， RoCE Spine-Leaf (叶脊)二组网为主(超大规模涉及三层)。通常无阻塞组网(上下行1:1) |
| 4 | 延时要求 | 标准以太网 50us (微秒)(TCP / IP) 或以上 | RDMA绕过OS，时延在 5us(RoCE) 或 2us(IB) |
| 5 | 系统维护 | 以太网非常成熟，基本上无门槛 | 对 RDMA，IB 需要专门的维护工具，RoCE 专门调优人才，门槛较高。 |

总结：智算中心的网络规划主要体现在大带宽，低时延的性能方面，且演变为 Spine-Leaf 网络拓扑

# 1. RDMA、IB、RoCE

- **RDMA** , Remote Direct Memory Access, 「远程直接内存访问」，是一种高性能网络通信技术。它允许一台计算机的网卡直接访问另一台计算机预先注册的内存区域，从而减少操作系统内核和 CPU 对数据传输的参与。
注意⚠️：所谓 “绕过CPU” 主要指大批量数据搬运过程。连接建立，内存注册，任务提交仍然需要软件与 CPU 参与。
- **IB** , InfiniBand, 专门设计的高性能网络体系。它是一套完整的网络体系，包括链路层，传输层，交换网络，以及 RDMA 能力。常见于超级计算和 AI 集群。
- **RoCE**: RDMA over Converged Ethernet. 在以太网上承载 RDMA。它复用了 InfiniBand 的传输语义，但底层使用以太网。目前的数据中心比较常见。
- iWARP： 基于 TCP/IP 承载 RDMA，能够使用可路由 IP 网络, 但生态规模较小，是另一种RDMA的实现。

<aside>
💡

RDMA 与 IB、RoCE 的关系

RDMA 是一种高性能网络通信技术，不是一个网络协议。
IB 和 RoCE 是实现 RDMA 技术的具体协议/网络方案。逻辑上，IB、RoCE 是对 RDMA 的实现。不过 IB 不只是一个 RDMA 的具体协议，是一套完整的网络架构。RoCE 更像是在以太网上实现 RDMA 的网络协议。它们之间的关系如下：

```
RDMA：目标能力与通信模型
   ├── InfiniBand：专用网络体系
   ├── RoCE：基于以太网
   └── iWARP：基于 TCP/IP
```

</aside>

# 2. 智算中心的网络类型

- 「算力网络」: 用于 GPU 服务器集群内部互联，是智算中心 AI 训练多卡并行工作的关键。卡卡通信是 GPU 服务器内部，当需要跨服务器的时候，就需要高速 IB 网络或 RoCE 网络进行通信。
- 「存储网络」: 一方面实现存储设备互联(存储设备内部组网)，进行分布式存储，另一方面还要负责打通 GPU 集群到存储集群的数据传输。
- 「业务网络」: 下发各种任务, 各类数据, 并将 AI 训练, 推理等结果进行返回, 也用于通用算力集群
- 「管理网络」: 各类设备的监控和管理，资源利用率监控，故障警告，下发配置等。

![image.png](5%20%E7%BB%84%E7%BD%91%E6%8A%80%E6%9C%AF/image.png)

这个图中，中间是计算区，它通过 4 个网络(4个颜色的线)与外面连接，「紫色是计算网络」，「绿色是存储网络」，「橙色是业务网络」，「黑色是外管理网络」。
存储区不需要计算网络, 存储网络一方面自己内部互联, 实现分布式存储. 另一方面要和计算集群打通.业务网路都是需要打通的。管理网络也都要打通，主要通过带外管理(带宽以外的管理网络)的方式实现所有设备的监控。

# 3.  64 台 H100 组网方案

每台 H100 的网卡配置： 

> 
> 
> - 8 x 400Gb NDR IB 网卡(单口)用于算力集群互联，
> - 2 x 100Gb 以太网卡用于与存储网络互联。
> - 2 x 100Gb 以太网卡用于业务网络互联
> - 2 x 10Gb 以太网卡用于管理网络互联

## 网卡

H100 上一般配备 8 张 「NDR IB 网卡」。NDR IB，Next Data Rate，描述的是 InfiniBand 的速率代际，表示的是一种速率规格，一般指 400 Gb/s. 完整的写法是 NDR 400Gb IB，因为还有 NDR 200Gb IB。一般我们说 NDR 400Gb IB 指的是单端口。但是也可能是双端口。

ConnectX-7 是 Nvidia 提供的 NDR IB 网卡的一个具体的产品系列。ConnectX-7 提供是单端口 400 Gb/s 和 双端口 200 Gb/s，两者整卡总带宽都是 400 Gb/s.

## IB 交换机数量

IB 交换机数量只与 NDR IB 网卡有关。每台 H100 有 8 张 NDR IB 单口网卡，64 台就有 512 个 IB 网络端口。叶子 (Leaf) 交换机是 64 端口的，一半上行，一半下行，也就是一半的端口要连接上层的 Spine 交换机, 一半端口连接 GPU 服务器。所以每个交换机连接 GPU 的端口只有 32 个。

512 个端口对应 512 / 32 = 16个 Leaf 交换机。上一层的交换机 64 个端口，全部用于连接下层交换机。所以 16 个交换机总共 16 x 32 = 512 端口，512 / 64 = 8 台 Spine 交换机。 

所以总共需要 24 台 IB 交换机。即： 64 台 H100：64 x 8 = 512 个 400Gb IB 单口网卡，IB SW(Switch)数量 = (Leaf 512/32) + (Spine 512/32/2) = 24.  (512 / 32 是 leaf 交换机的数量，Leaf 交换机的端口只有一半会连接上层 Spine 交换机，即上层 Spine 交换机数目是 Leaf 交换机数目的一半。与前面 16 x 32 / 64 从端口角度计算出来的结果一样)。

![image.png](5%20%E7%BB%84%E7%BD%91%E6%8A%80%E6%9C%AF/image%201.png)

通常 AI GPU 服务器节点的数量是一定的，比如 64 台，128台等。

但是，存储节点和管理节点需要多少是不确定的，要根据实际情况，业务特点来进行规划 。我们既可以配置高性能的分布式存储，但是为了节约成本，也可以跑一些一般的存储。管理节点也可以按需配置，可以做虚拟化的资源池，然后按需做虚拟机，这里不做明确的限制。另外就是安全区域，现在一般要做三级等保。

# 4. 128 台 H100 组网方案

# 5. 网络架构典型问题

### ◼︎两层胖树(Spine-Leaf)与三层胖树(Spine-Leaf-Core)

NDR 400Gb IB 网卡， 2 层 Spine-Leaf 架构最多支持多少个节点(网卡)。什么时候需要三层组网，三层组网的上限是多少？

![image.png](5%20%E7%BB%84%E7%BD%91%E6%8A%80%E6%9C%AF/image%203.png)

对于「两层胖树 Leaf-Spine」，有公式

$$
N_{max} = P^2/2
$$

$N_{max}$ 表示可支持的最大 GPU 卡数量。 P 代表使用单个交换机的端口数。因此，如果交换机的端口数是 64. 这种两层结构，最多可以接 2048 个 GPU。

<aside>
💡

注意⚠️：这里是对应 GPU 卡的数量，实际上是对应 400Gb IB 网卡数量。这里是假设在 8卡 GPU 服务器里，一张 GPU 对应一张 400Gb IB 网卡。如果说机器数的话，还要除以 8 ，即 2048 / 8  = 256台。

</aside>

对于「三层胖树 Leaf-Spine」。有公式

$$
N_{max} = P^3 /4
$$

### ◼︎ 交换机跳数最少

H100 SXM 8卡机的 8 张网卡和 NDR IB 交换机互联时，要尽量做到中间跳转的跳数要最少。对于两层胖树架构，智算节点(GPU 服务器)间的同 GPU 卡号转发跳数为 1 跳。智算节点(GPU 服务器)间不同 GPU 卡号在没有做智算节点内部路径优化的情况下转发跳数为 3。

![image.png](5%20%E7%BB%84%E7%BD%91%E6%8A%80%E6%9C%AF/image%204.png)

具体的网络架构优化如下：

一台 IB 交换机有 64 个端口，Leaf 交换机 32 个下行端口连接 GPU 服务器，32 个上行端口连接上层 Spine 交换机。我们分别讨论，Leaf 交换机与 GPU 服务器的连接，和 Leaf 交换机与上层 Spine交换机的连接。以 H100 8卡服务器，64台集群为例：

<aside>
💡

Leaf 交换机与 GPU 服务器连接

标准 H100 服务器有 8 张显卡，每张对应一个 NDR IB 网卡，相当于是每张 GPU 都有自己的网卡对外连接。

- 将 64 台 GPU 编号 1～64。在每台 GPU 服务器内部将 8 张 GPU 也进行编号 1～8。
- 将所有编号为 1 的 GPU 连接到同一个 IB 交换机中，然后将所有编号为 2 的 GPU 连接到下一个交换机中….以此类推。
- 一个 IB 交换机有 32 个下行端口，所以 1 号 交换机可以连接 32 台机器。我们将 32 台 GPU 服务器和 8 台 Leaf 交换机作为一个组 Group。
- 在 Group 内部，所有 32 台 GPU 服务器的 1号 GPU 都连接到 1 号交换机，2号 GPU 连接到 2 号交换机…。8 张 GPU，连接在 8个 不同的交换机上。 32 台 GPU 服务器都按这种方式连接。每台交换机 32 个端口连接了所有 32 台机器的同一个编号的 GPU。每台机器内部的 8 张 GPU 也连接了全部的 8 个交换机。
- 64台 H100, 分成了两组。第 2 组是编号 33 ～ 64 的 GPU。同样，每台 GPU 内部编号为1 的 GPU 连接到 1 号交换机。1 号交换机连接了组内所有 32 台服务器的 1 号 GPU，2号交换机连接了组内所有 2 号 GPU….。8 台交换机分别连接了组内 32 台 GPU 服务器内的 1 ～ 8 号 GPU。而一台 GPU 服务器的 8 张 GPU，连接了全部 8 台交换机。
</aside>

这样的连接方式让组内任意编号相同的 GPU 之间跨服务器通信，只需要 1 跳。而 GPU 服务器内部GPU 间的通信，是 NvLink。这样跳数最少。

这样，2 个 Group, 每个 Group 内，32 台服务器的 8 张 GPU 分别连接 8 台交换机。32 台服务器刚好对应交换机的32个端口，8 张 GPU 刚好对应 8 台交换机。这样刚好全部对上。

<aside>
💡

Leaf 交换机 与 Spine 交换机的连接

Leaf 交换机的上行连接端口有 32 个，但是因为是两层胖树， Spine 交换机不用再向上连接了，所以 64 个端口，都连接下层 Leaf 交换机。

- 每个 Leaf 交换机有 32 个端口，分为 8 组，每组 4 个。8 组端口分别连接 8 个 Spine 交换机，组内的 4 个端口连接到同一个交换机。
- 16 台 Leaf 交换机连接按这种方式连接上层 8 台 Spine 交换机
- 每一台 Leaf 都连接了全部 8 台 Spine。每一台 Spine 也连接了全部 16 台 Leaf。
</aside>

这样的连接方式，让任何一台 Leaf 要找到另一台 Leaf, 中间也只经过一跳。跳数最少。

### 网卡模块和线缆规划

当 GPU 服务器数量和 IB 交换机数量定了以后。然后就是网卡模块和线缆的规划。需要的机柜功率，有 10KW，20KW，30KW等等，一个机柜放几台 H100，设备分布等等。这些需要看图纸，以及实地调研才能确定线缆规格。

![image.png](5%20%E7%BB%84%E7%BD%91%E6%8A%80%E6%9C%AF/image%205.png)

注意⚠️：线缆品牌一定要选大品牌，否则故障率会很高。

上图是一个机柜放了 4 台 H800(H100阉割版)，这种情况并不常见，因为这样的机柜应该是 40KW 以上。一般 10+KW 的机柜就放一台，最多 20+KW 的机柜放两台。

### ◼︎ 生产可视化与监控

在实际业务中，IB 网络，PCIe利用率，NvLink 带宽是否饱和等，这些状态需要监控。通常需要配一套监控的系统。
