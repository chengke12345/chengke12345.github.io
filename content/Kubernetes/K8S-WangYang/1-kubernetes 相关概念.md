# 1.基础设施的迭代

## 单机场景

单机场景下，三种部署方式的演进方式为

![[Pasted image 20261022143357.png]]

<font color="orange">[传统方式部署],Traditional Deployment</font>: 最下面是硬件 (如 Dell R620 服务器)，中间是操作系统(如 CentOS), 最上面就是跑的应用 (如 MySql, Nginx 等)。

>- 问题：这样的部署方案，最大的问题是安全性。比如，在 APP 上我们跑了 Apache, Mysql, Nginx。当 Apache 被劫持的时候, 由于它们在一台物理机上，很可能 MySql 的数据目录就被分享出去了，Mysql 的数据就泄漏了。  
>- 如果要把 APP 不放在同一台物理机，那是对机器性能的巨大浪费。比如就运行一个 Apache，它是消耗不了机器性能的。需要多个应用一起消耗当前物理机资源，否则就有大量闲置。这里就有一个平衡。<u><b>资源利用率高，安全性就会下降，如果要安全性上升，资源利用率就会下降</b></u>。

但是「安全性」和「资源利用率」我们都要。因此进化到第二代部署方式。

<font color="orange">[虚拟化部署], Virtualized Deployment </font>：底层的硬件和操作系统不变。但出现了「虚拟化层, Hypervisor」，有了虚拟化层，就可以在一个物理机里面运行多个虚拟机 VM。每一个虚拟机里可以运行完全独立的应用，比如一个虚拟机跑 Apache, 另一个 跑 Nginx。如果出现安全问题，不同虚拟机是完全隔离的，即使一个应用被劫持，其他虚拟机也是安全的。

>- 问题：VM部署方式下，除了本机操作系统外，每个虚拟机还要运行各自的操作系统。随着虚拟机数量的增加，不得已提供虚拟机的数量也会增加，就会浪费更多的系统资源。
>- 所以它虽然提高了系统资源利用率，但是相当一部分是供给给系统虚拟化本身的支撑，而不是应用消耗。如果企业只有少量服务器还好，大厂大量服务器下，10000 台机器，每个机器浪费 2 GB 内存, 这样 2万 GB 的内存就没了。

所以，行业出现了第三种部署方案，以容器方案为首的部署方案

<font color="orange">[容器化部署]，Container Deployment</font>：底层硬件和操作系统不变。上面出现了 「Container Runtime，容器运行时系统」，然后应用放在不同的容器空间中，彼此隔离。多个容器，每个容器运行不同的应用程序，但没有传统虚拟化方式虚拟机本身的系统消耗。所以，<u><b>容器化部署既保证了应用彼此隔离，又不像传统虚拟化技术，随虚拟机增加，浪费就会增多。</b></u>

但是，容器的安全性相对传统虚拟机技术，一定是下降的。但是超过了及格线，比如安全性满分 10分，虚拟机 9.8 分，容器能达到 7、8分。但是在资源利用率上，容器远远大于传统虚拟化。

## 集群场景

上面都是一台机器的部署方式。随着应用变大，用户数量指数上升，背后的服务器数量也在上升，现在就需要集群化的解决方式。

### IAAS

首先就是 <font color="#45ce6e">「IAAS, Infrastructure as  a Service」,基础设置即服务</font>。

![[Pasted image 20261022155239.png]]

IAAS 是当前云计算的一种分类。IAAS 就是用多台物理机(上图从左到右是 3 台物理机)，每台物理机通过 Hypervisor 虚拟化层，虚拟出来多个虚拟机，每个虚拟机上跑不同的应用。多个物理机组合在一起，就是一个 IaaS 的场景。

> [!NOTE] OpenStack
>- 当物理机的数量不断增加，直到数千数万台的时候，如果我们想要选择一台机器安装部署应用的时候，逻辑上应该选择这数万台机器里面，资源剩余最多的一台，让它去运行应用，这样是最好的。但是从数万台机器中选出一台，这个工作不可能人来做。
>- 这时我们就会使用一个工具，叫做 <font color="#45ce6e">「OpenStack」</font>, 这是 IAAS 方向上最主流的框架。它的作用，就是在当前物理机层面上，组建成一个集群或叫管理器。用户需要创建虚拟机时，不需要从1万台机器里挑一个剩余资源最多的，只需要让用户向平台发送请求，OpenStack 平台就会自动从多个物理机里选择当前资源剩余量最大的那一台物理机，并且自动帮你创建出来一台虚拟机，然后再把当前虚拟机的访问接口返回给用户，这样用户就不需要自己执行选择过程了。这其实体现了 IAAS 的思想概念。
>
>![[Pasted image 20261022162615.png]]
>
>OpenStack 有一个特性，它的规模越大，成本越低。未来以 IAAS 为主提供服务的云厂商，一定只有几家，因此它后面的技术路线时越来越窄的。 

### PAAS

集群化部署的第二种方案就是 <font color="#45ce6e">「PAAS, Platform as a Service」, 平台即服务</font>。
IAAS 模式下，用户向供应商提出一个需求，它返回一个虚拟机或系统。用户可以在上面去部署应用。对于平台即服务，系统就不需要用户自己部署了，环境也不需要用户部署，只需要把用户的应用扔进去，就可以提供访问，它的底层就是使用「容器及虚拟化」去做的。

![[Pasted image 20261022165257.png]]

底层的硬件和操作系统仍然不变，在此之上跑的是容器运行时 Container Runtime。每个应用以一个容器方案在当前机器上被运行。类似于 IAAS 的 OpenStack，<font color="orange">这些物理机也需要被一些平台统罩，比如 Kubernetes, Rancher, Mesos 等</font>。

<font color="#eb4349">「我们讨论的 kubernetes 就是 PAAS 的管理物理机的统一平台的框架方案」</font>, 当然也还有其他解决方案，比如 Docker Swarm, Mesos 等等。 

### SAAS

<font color="#45ce6e">「SAAS， Software as a Service」,软件即服务</font>，它更像是一种软件层面的多租户的场景。

![[Pasted image 20261022170123.png]]

### PAAS 几种方案对比

PAAS 的主流实现有这么几个方向 Docker Swarm, Mesos, Kubernetes

![[Pasted image 20261022171001.png]]

<font color="orange">[Docker Swarm]</font>: 是由 Docker 公司开发的集群化的管理软件，用以实现 Paas 的一个框架。用户只要告诉它，需要运行一个容器，它就会从多台物理机中，选择一个最靠谱的去运行当前容器，不需要用户手动选择。
它的特点是「轻」，会了 Docker 之后的学习成本极低。代码轻，它被直接集成在 docker 的软件包内，只需要直接执行 `docker swarm init` 就可以初始化出来一个集群。十分方便。
因为轻，它功能就有限，Docker 公司主要是做好几个核心概念，更多的留给企业二次开发。但是，有能力做二次开发的企业极少。Docker Swarm 的缺点会随着使用量级的增加而逐渐暴露。

<font color="orange">[Apache Mesos]</font>: 它诞生的时间比较久了，在整个行业中，为大量企业提供了技术支撑。Twitter就是其中一个拥趸，但是19年开始，Twitter 已经全面从 Mesos 转向了 Kubernetes.

<font color="orange">[Kubernetes]</font>: 这是 Google 基于它之前的一些技术，迭代出来的一个「集群管理软件」，也叫「资源管理系统」。它在相当多的一些选项和功能上与竟品甩开了差距。现在整个行业以 Kubenetes 为主了。

# 2. Kubernetes 优势

- <font color="orange">服务发现和负载均衡</font>。Kubernetes 默认自带。传统集群，我们可能需要部署 nginx 服务。用户访问负载调度器，然后负载调度器再把用户访问转给第一个业务服务器，或第二个，或第三个....这需要手动搭建。但在 kubernetes 里面，只需要一条命令就可以创建一个负载均衡的集群。

- <font color="orange">存储编排</font>。如果要在 Kubernetes 中使用存储资源，也只需要一条命令的方案，就可以调用。云环境中还可以按使用量计费，比如需要一个存储，10个G, 那就可以收取 10G /月 的金额。

- <font color="orange">自动部署与回滚</font>。Kubernetes 可以帮助我们直接默认实现一部分 Devops 的功能。比如，自动部署，以及回滚等(只需要一条命令 rollout, 就可以从 v1.1 回滚到 v1.0)。

- <font color="orange">自动分配 CPU/内存资源-弹性伸缩</font>。传统方案里，我们需要自己选择哪台机器剩余资源更多，以此部署新的应用。在 Kubernetes 里我们只需要把怎么部署，部署什么告诉 Kubernetes 集群，它会自动帮你挑选当前最合适的最佳节点，来运行应用。「弹性伸缩」就是甚至允许指定一个 CPU 阈值，比如 80%，当前应用 CPU 使用率超过 80%，就自动扩展到两个节点上运行。

- <font color="orange">自我修复</font>。<u><b>这是最核心的功能</b></u>。传统虚拟化要做自我修复的代价太大了。容器有一个特性叫秒级启动。一个容器里面运行的一个应用死掉了，kubernetes 就会瞬间创建一个新的容器把它顶体掉，因为代价很低，可以随意抛弃。容器可以做自我修复，就是因为代价足够低。

- <font color="orange">Secret(安全相关信息) 和配置管理</font>。Kubernetes 集群会对系统中敏感和特殊的数据做一个新的处理方案,「Secret」, 它会对敏感数据编码，除非解码，否则任何人都无法看到原版数据。

- <font color="orange">大型规模的支持</font>。Kubernetes 单个集群或者也叫做，kubernetes 单个节点，支持的最大规模，官方给出了一个建议数值。
  注意⚠️：<font color="#eb4349">这是 Kubernetes 单个集群/单个节点最大容量。如果还有更多机器，可以分成多个 Kubernetes 集群。多集群可以互相访问。所以，这里说的是「单个 Kubernetes 最大节点数」。</font>
  ✅ 每个节点的 Pod 数量不超过 110。
  ✅ 节点数目不超过 5000，即机器数量。
  ✅  Pod 总数不超过 150000。
  ✅ 容器总数不超过 30000。
  Kubernetes 不会成为公司的瓶颈。Google 都在用 Kubernetes 作为底层的资源管理平台。 

- <font color="orange">开源</font>。开源是 Kubernetes 产生如此大影响力的关键因素。Kubernetes 现在这么厉害，是因为它自己也是踩在前人的肩膀上。
